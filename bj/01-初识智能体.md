# 《第一章 初识智能体》【面试+进阶学习专用笔记】
特点：通俗理解 + 标准术语 + 案例 + 关键边界辨析，既能看懂，面试口述、衔接后续章节都够用。
## 一、智能体（Agent）基础概念
**标准定义**
智能体是一套实体，能够依靠传感器感知环境，凭借自主性，通过执行器执行行动，持续朝着目标和环境交互。
完整闭环：**感知 → 思考 → 行动 → 获取反馈（观察）**，循环往复。
四大核心要素：环境、传感器、执行器、**自主性（区分普通脚本/程序的核心标志）**
> 面试高频坑：单纯高性能计算机、固定流程脚本≠智能体，缺少自主决策闭环。

## 二、两大时代：传统智能体 VS LLM智能体
### （1）传统智能体（AIMA经典分类，必背）
1. **简单反射智能体**
逻辑：只依靠当下感知，内置固定「条件→动作」规则；无记忆。
例子：家用恒温器。
局限：只能处理当下信息，无法理解上下文。

2. **基于模型的反射智能体**
逻辑：内部维护**世界模型（记忆）**，记录环境中无法直接观测的信息。
例子：隧道里行驶的自动驾驶车辆，看不见前车，但持续记录车辆位置。

3. **基于目标的智能体**
逻辑：以目标为导向，主动搜索、规划行动路径。
例子：车载GPS导航，规划路线抵达目的地。

4. **基于效用的智能体**
逻辑：存在多个互相冲突的目标，引入效用值权衡方案，追求综合最优。
例子：出行同时兼顾时间、费用、舒适度。

5. **学习型智能体**
逻辑：自带学习模块，通过和环境交互试错，持续优化策略；强化学习是主流实现方式。
例子：AlphaGo Zero自我对弈进化。

### （2）LLM驱动智能体（现代新范式）
传统智能体：规则、策略全部由人工预先编写，能力边界固定。
LLM智能体：依托预训练形成隐式世界模型，具备涌现能力。
核心特征：
1. 可理解模糊自然语言需求
2. 自主完成任务拆解
3. 主动识别信息缺口、调用外部工具
4. 根据反馈动态调整方案
标准运行范式：**Thought-Action-Observation 循环**

## 三、智能体三大分类体系（面试经常提问）
### 分类1：按照决策响应特性
1. **反应式智能体**
即时响应、延迟低；缺点：短视，缺少长期规划。
适用：防撞系统、高频交易。
2. **规划式（审议式）智能体**
行动前推演多条未来路径，长远决策；缺点：计算开销大，容易错失时机。
适用：棋局AI、长期方案规划。
3. **混合式智能体**
同时具备快速反应 + 长期规划能力。**当前LLM智能体主流架构**。

### 分类2：按照知识表示范式
1. **符号主义AI**
知识是显式规则、逻辑、图谱；优势可解释；短板：遇到规则外场景极易失效（知识获取瓶颈）。
2. **亚符号主义（连接主义/神经网络）**
知识隐含在网络权重中，类似人的直觉；擅长非结构化数据识别；短板：黑箱，容易产生幻觉。
3. **神经符号主义AI（融合方向）**
类比卡尼曼《思考，快与慢》
系统1（快思考）：亚符号，直觉、快速模式识别
系统2（慢思考）：符号推理，严谨逻辑判断
> LLM智能体是神经符号主义典型落地实践，也是后续高级Agent学习重点。

## 四、智能体运行底层理论
### 1. PEAS模型（标准化描述任意智能体任务环境）
- Performance：性能指标，评判智能体好坏的标准
- Environment：智能体所处外部场景
- Actuators：执行器，作用于环境的手段
- Sensors：传感器，采集环境信息

常见环境属性：部分可观测 / 确定/随机环境 / 单/多智能体环境 / 动态环境 / 序贯环境。

### 2. Agent Loop 智能体循环
1. 感知：接收环境观察
2. 思考：任务规划 + 工具选择
3. 行动：调用工具作用于环境
环境发生变化，产生新观察，再次进入循环。

### 3. Thought-Action-Observation交互协议（工具智能体基石）
- Thought：模型内部推理、思考过程
- Action：工具调用指令；`Finish[]`代表任务终止
- Observation：工具执行结果，整理后交给模型作为下一轮输入
> 所有框架（LangGraph、AutoGen、CrewAI）底层都离不开这套思想。

## 五、实战案例：旅行助手智能体（工程落地最小Demo）
整套组件：系统提示词（Prompt）、工具函数、兼容OpenAI协议的LLM客户端、循环调度器
运行流程：
用户需求 → LLM思考确定需要调用工具 → 执行工具拿到结果 → 结果封装为Observation传回模型 → 循环直到任务结束。
验证三大核心能力：任务分解、工具调用、上下文持续交互。

## 六、智能体两种落地协作模式
1. **作为人类辅助工具**
定位：增强人的工作流，人主导决策。
产品：GitHub Copilot、Cursor、Claude Code。

2. **自主协作者智能体**
定位：接收高层目标，自主规划、执行、反思。
主流框架：AutoGen、CrewAI、MetaGPT、LangGraph
架构方向：
① 单智能体自主循环
② 多智能体分工协作（角色扮演、虚拟团队）
③ 基于状态图的高级控制流（LangGraph）

## 七、核心重难点：Workflow VS Agent（面试高频问答题）
**Workflow（工作流）**
预先写死全部步骤、判断分支；流程固定、确定性高。
适合：场景稳定、规则清晰、需求标准化的业务。
优点：稳定、易测试、成本可控；缺点：难以应对未知、多变场景。

**Agent（智能体）**
仅给定最终目标，中间步骤由模型自主动态生成、调整方案。
适合：需求模糊、环境动态变化、存在大量未知情况。
优点：灵活自适应；缺点：行为不可完全预测，调试难度高。

混合方案思路：常规标准化流程走Workflow；遇到异常、复杂场景交由Agent处理。

## 八、本章核心总结（面试可以直接用来收尾）
1. Agent不是新概念，大模型解决了传统智能体通用性不足的痛点；
2. 判断智能体核心标准：持续感知-思考-行动-反馈闭环 + 自主目标导向决策；
3. LLM智能体最简公式：大模型大脑 + 工具调用能力 + 持续交互循环；
4. 工程选型经验：固定自动化优先Workflow；复杂、开放场景选择Agent。
