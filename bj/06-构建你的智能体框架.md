# 知识点总结 + 完整可运行代码
## 核心知识点
1. `HelloAgentsLLM`原生支持所有**OpenAI兼容接口**，但各家平台环境变量、接口地址、默认模型不一样，切换服务商麻烦。
2. 引入`provider`：把每个平台的配置细节封装起来，对外提供统一调用方式。
3. **扩展框架最佳实践：继承，不修改框架源码**
   - 修改框架内部源码，后续框架升级会覆盖你的代码；
   - 新建子类继承`HelloAgentsLLM`，重写`__init__`实现新平台适配。
4. 重写逻辑：判断`provider`，匹配到自定义平台执行专属配置；其他情况使用`super()`调用父类原有逻辑。
5. 父类所有方法（think等）会自动继承，不用重复编写。

```python
import os
from typing import Optional
from openai import OpenAI
from hello_agents import HelloAgentsLLM


class MyLLM(HelloAgentsLLM):
    """
    继承框架原生HelloAgentsLLM，外部扩展适配ModelScope平台
    """
    def __init__(
        self,
        model: Optional[str] = None,
        api_key: Optional[str] = None,
        base_url: Optional[str] = None,
        provider: Optional[str] = "auto",
        **kwargs
    ):
        # 适配ModelScope平台
        if provider == "modelscope":
            print("正在使用自定义的 ModelScope Provider")
            self.provider = "modelscope"

            # 优先使用传入参数，无参数则读取环境变量
            self.api_key = api_key or os.getenv("MODELSCOPE_API_KEY")
            self.base_url = base_url or "https://api-inference.modelscope.cn/v1/"

            # 校验密钥
            if not self.api_key:
                raise ValueError("未找到MODELSCOPE_API_KEY，请在.env配置密钥")

            # 模型参数配置
            self.model = model or os.getenv("LLM_MODEL_ID") or "Qwen/Qwen2.5-VL-72B-Instruct"
            self.temperature = kwargs.get('temperature', 0.7)
            self.max_tokens = kwargs.get('max_tokens')
            self.timeout = kwargs.get('timeout', 60)

            # 创建OpenAI兼容客户端发起请求
            self._client = OpenAI(
                api_key=self.api_key,
                base_url=self.base_url,
                timeout=self.timeout
            )
        else:
            # 非modelscope，交给父类原有逻辑处理
            super().__init__(
                model=model,
                api_key=api_key,
                base_url=base_url,
                provider=provider,
                **kwargs
            )
```

# 7.2.2 本地模型调用｜知识点 + 完整代码
## 一、核心知识点
### 1. 两种本地运行模型方案对比
1）**Transformers原生直接运行模型**
本地加载模型、Python内直接推理；
✅ 优点：简单、适合学习调试
❌ 缺点：并发性能差，**不适合生产环境**

2）**高性能推理服务（VLLM / Ollama）【推荐】**
底层使用PagedAttention、连续批处理技术，大幅提升吞吐；
把本地模型封装成 **兼容OpenAI格式的HTTP接口**。
> 关键好处：接口标准化！云端大模型、本地模型共用同一套HelloAgentsLLM代码，切换只改配置。

- 定位：高性能GPU推理库，适合显卡部署、高并发场景
- 启动后提供地址：`http://localhost:8000/v1`

### 3. Ollama
- 定位：极简本地模型管理工具，一键下载、启动模型，上手门槛低
- 启动后提供地址：`http://localhost:11434/v1`

### 4. 统一接入核心原理
VLLM、Ollama 对外提供 **OpenAI兼容接口**，所以不需要重写自定义LLM类！
直接使用原生`HelloAgentsLLM`，只修改 `base_url、model、provider` 参数，智能体业务代码完全不用改动。

### 5. 重要细节
本地推理服务**不需要合法api_key**，随便填写任意字符串占位即可。

# 7.2.3 自动检测机制｜知识点 + 模拟实现代码
## 一、核心知识点
### 1. 设计思想：约定优于配置
目标：尽量减少开发者手动填写 `provider`、地址、密钥。
`HelloAgentsLLM` 依靠两个内部方法配合完成自动识别：
1. `_auto_detect_provider()`：**自动推断服务商名称provider**
2. `_resolve_credentials()`：**根据识别出的provider，加载对应密钥、默认接口地址**

### 2. provider自动检测优先级（从高到低）
1. **优先检测服务商专属环境变量（最高优先级）**
存在`MODELSCOPE_API_KEY` / `OPENAI_API_KEY`，直接锁定服务商。
2. **解析base_url地址判断**
读取`LLM_BASE_URL`，通过域名、端口识别：
- 包含`11434` → Ollama
- 包含`8000` → VLLM
- 云端域名`api-inference.modelscope.cn` → ModelScope
3. **辅助：API密钥前缀特征判断（兜底，可信度低）**
4. 全部识别失败，标记为`auto`，使用通用配置

### 3. 两个方法分工
- `_auto_detect_provider`：**判断是谁（哪个服务商）**
- `_resolve_credentials`：**给这个服务商配齐密钥、接口地址**

### 4. 带来的好处
代码不用硬编码provider，切换模型只改.env环境变量；
云端模型、本地Ollama/VLLM无缝切换，上层Agent代码零改动。

### 5. 使用特点
```python
# 不用写provider=xxx，框架自动识别
llm = HelloAgentsLLM()
```

## 二、模拟框架核心代码（可直接理解逻辑）
> 注意：这是原理模拟代码，方便看懂框架内部运作，不是hello_agents库源码
```python
import os
from typing import Optional, Tuple

class DemoLLM:
    def __init__(self, api_key: Optional[str] = None, base_url: Optional[str] = None, provider="auto"):
        # 1. 如果用户没有手动指定provider，则自动检测
        if provider == "auto":
            self.provider = self._auto_detect_provider(api_key, base_url)
        else:
            self.provider = provider

        # 2. 根据provider解析密钥、接口地址
        self.api_key, self.base_url = self._resolve_credentials(api_key, base_url)
        print(f"自动识别完成，当前provider：{self.provider}")

    def _auto_detect_provider(self, api_key: Optional[str], base_url: Optional[str]) -> str:
        """自动检测服务商provider"""
        # 优先级1：检测专属环境变量
        if os.getenv("MODELSCOPE_API_KEY"):
            return "modelscope"
        if os.getenv("OPENAI_API_KEY"):
            return "openai"

        # 获取通用环境变量
        actual_api_key = api_key or os.getenv("LLM_API_KEY")
        actual_base_url = base_url or os.getenv("LLM_BASE_URL")

        # 优先级2：通过base_url识别
        if actual_base_url:
            url = actual_base_url.lower()
            if "api-inference.modelscope.cn" in url:
                return "modelscope"
            if ":11434" in url:
                return "ollama"
            if ":8000" in url:
                return "vllm"

        # 优先级3：密钥格式辅助判断（示例）
        if actual_api_key and actual_api_key.startswith("ms-"):
            return "modelscope"

        # 识别失败，使用通用auto模式
        return "auto"

    def _resolve_credentials(self, api_key: Optional[str], base_url: Optional[str]) -> Tuple[str, str]:
        """根据provider填充密钥、默认接口地址"""
        if self.provider == "modelscope":
            key = api_key or os.getenv("MODELSCOPE_API_KEY") or os.getenv("LLM_API_KEY")
            url = base_url or os.getenv("LLM_BASE_URL") or "https://api-inference.modelscope.cn/v1/"
            return key, url
        elif self.provider == "ollama":
            key = api_key or "ollama"
            url = base_url or os.getenv("LLM_BASE_URL") or "http://localhost:11434/v1"
            return key, url
        elif self.provider == "vllm":
            key = api_key or "vllm"
            url = base_url or os.getenv("LLM_BASE_URL") or "http://localhost:8000/v1"
            return key, url
        else:
            # 通用兜底
            key = api_key or os.getenv("LLM_API_KEY")
            url = base_url or os.getenv("LLM_BASE_URL")
            return key, url
```

# 7.3.1 Message 类｜知识点 + 完整代码
## 一、核心知识点
### 1. 设计目的
统一规范智能体和大模型交互的对话消息，标准化上下文管理。
- 对内：使用面向对象 `Message` 对象，附带时间戳、扩展元数据，方便日志、调试、后续上下文处理；
- 对外：提供 `to_dict()` 方法，转换成 OpenAI 标准消息字典，直接传给 LLM 接口。
> 设计原则：**对内丰富扩展，对外接口兼容**

### 2. 关键技术点
1. **继承 `pydantic.BaseModel`**
自带数据校验，方便序列化、参数规范。
2. **`Literal` 限定角色类型**
`role` 只能是 `user / assistant / system / tool`，杜绝非法字符串，实现类型安全，对齐 OpenAI 消息规范。
3. 字段划分
- 必填核心：`content` 消息内容、`role` 消息角色
- 扩展预留：`timestamp` 消息时间、`metadata` 自定义扩展字典（日志、标签、工具返回信息等）
4. `to_dict()` 核心方法
框架内部操作 Message 对象，调用模型时统一转为 `{"role":"xxx","content":"xxx"}` 标准格式，供 `llm.think(messages)` 使用。
5. 重写 `__str__`
方便打印调试，直观查看消息。

### 3. 业务价值
所有智能体、工具调用、对话上下文全部使用同一套 Message 结构；后续新增功能（上下文窗口裁剪、消息持久化、多模态消息）只需要扩展此类，上层代码改动极小。

## 二、完整代码 message.py
```python
"""
message.py
统一消息模型，规范智能体与LLM交互的对话格式
"""
from typing import Optional, Dict, Any, Literal
from datetime import datetime
from pydantic import BaseModel

# 限定合法的消息角色，和OpenAI接口标准对齐
MessageRole = Literal["user", "assistant", "system", "tool"]


class Message(BaseModel):
    """
    框架统一消息实体
    """
    content: str
    role: MessageRole
    timestamp: datetime = None
    metadata: Optional[Dict[str, Any]] = None

    def __init__(self, content: str, role: MessageRole, **kwargs):
        super().__init__(
            content=content,
            role=role,
            # 不传时间戳则自动赋值当前时间
            timestamp=kwargs.get("timestamp", datetime.now()),
            metadata=kwargs.get("metadata", {})
        )

    def to_dict(self) -> Dict[str, Any]:
        """
        转为OpenAI API兼容字典，调用LLM时使用
        """
        return {
            "role": self.role,
            "content": self.content
        }

    def __str__(self) -> str:
        """打印对象时的格式化文本，便于调试"""
        return f"[{self.role}] {self.content}"
```

1. 程序中创建 `Message` 对象管理对话；
2. 需要请求大模型时，调用 `.to_dict()`；

```python
"""
config.py
集中式全局配置管理
"""
import os
from typing import Optional, Dict, Any
from pydantic import BaseModel


class Config(BaseModel):
    """HelloAgents 全局配置类"""
    # LLM相关配置
    default_model: str = "gpt-3.5-turbo"
    default_provider: str = "openai"
    temperature: float = 0.7
    max_tokens: Optional[int] = None

    # 系统运行配置
    debug: bool = False
    log_level: str = "INFO"

    # 智能体上下文配置
    max_history_length: int = 100

    @classmethod
    def from_env(cls) -> "Config":
        """
        从环境变量加载配置，环境变量会覆盖默认值
        """
        return cls(
            debug=os.getenv("DEBUG", "false").lower() == "true",
            log_level=os.getenv("LOG_LEVEL", "INFO"),
            temperature=float(os.getenv("TEMPERATURE", "0.7")),
            max_tokens=int(os.getenv("MAX_TOKENS")) if os.getenv("MAX_TOKENS") else None
        )

    def to_dict(self) -> Dict[str, Any]:
        """转为字典，用于日志打印、序列化"""
        return self.model_dump()
```

# 7.3.3 Agent 抽象基类｜知识点 + 完整代码
## 一、核心知识点
### 1. 设计目的
定义所有智能体**统一标准接口**。抽象类只规定「智能体有哪些能力」，不规定「能力怎么实现」。
统一规范：不管是简单对话智能体 `SimpleAgent`、工具推理智能体 `ReActAgent`，外部调用方式完全一致。

### 2. 核心技术：`ABC` + `@abstractmethod`
1. `ABC`：抽象基类标记，**不能直接 new Agent() 实例化**，只能被子类继承。
2. `@abstractmethod` 抽象方法 `run()`
强制**所有子类必须实现run方法**；子类不实现，代码运行直接报错。
保证全部Agent拥有统一入口：`agent.run("用户问题")`。

### 3. 基类内置通用能力（所有Agent共享）
无需每个子类重复编写：
- 消息历史管理：`add_message` / `get_history` / `clear_history`
- 内置成员：名称、LLM客户端、系统提示词、全局配置、对话历史 `_history`
- 历史列表使用 `Message` 对象，和消息组件联动

### 4. 依赖关系梳理
Agent 依赖三大核心组件：
1. `HelloAgentsLLM`：负责调用大模型
2. `Message`：标准化对话消息，维护上下文
3. `Config`：全局配置参数

### 5. 工程价值
1. 外部业务代码无需关心Agent内部逻辑，统一调用 `run()`；
2. 新增一类智能体，只需要继承Agent，实现run方法即可，上层调用代码不用修改；
3. 通用功能（历史管理）放在父类，避免大量重复代码。

### 优先级思想
父类存放**通用逻辑**；
子类实现**差异化执行逻辑**。

## 二、完整代码 agent.py
```python
"""
agent.py
Agent 抽象基类，所有智能体的父类
"""
from abc import ABC, abstractmethod
from typing import Optional, Any
from .message import Message
from .llm import HelloAgentsLLM
from .config import Config


class Agent(ABC):
    """
    智能体抽象基类
    不能直接实例化，所有自定义Agent需要继承此类并实现run方法
    """
    def __init__(
        self,
        name: str,
        llm: HelloAgentsLLM,
        system_prompt: Optional[str] = None,
        config: Optional[Config] = None
    ):
        # 智能体名称
        self.name = name
        # 大模型客户端依赖
        self.llm = llm
        # 系统提示词
        self.system_prompt = system_prompt
        # 全局配置，不传则使用默认Config
        self.config = config or Config()
        # 对话历史，存储Message对象
        self._history: list[Message] = []

    @abstractmethod
    def run(self, input_text: str, **kwargs) -> str:
        """
        智能体执行入口，子类必须实现
        :param input_text: 用户输入文本
        :return: 模型回复字符串
        """
        pass

    def add_message(self, message: Message):
        """追加消息到对话历史"""
        self._history.append(message)

    def clear_history(self):
        """清空全部对话上下文"""
        self._history.clear()

    def get_history(self) -> list[Message]:
        """获取历史消息副本（防止外部直接篡改内部列表）"""
        return self._history.copy()

    def __str__(self) -> str:
        """打印智能体信息，方便调试"""
        return f"Agent(name={self.name}, provider={self.llm.provider})"
```

```python
class SimpleAgent(Agent):
    def run(self, input_text: str,** kwargs) -> str:

        user_msg = Message(content=input_text, role="user")
        self.add_message(user_msg)

        # 拼装消息列表，调用LLM
        messages = []
        if self.system_prompt:
            messages.append(Message(content=self.system_prompt, role="system").to_dict())
        for msg in self.get_history():
            messages.append(msg.to_dict())

        # 请求模型
        resp = self.llm.chat(messages)
        assistant_msg = Message(content=resp, role="assistant")
        self.add_message(assistant_msg)
        return resp
```

# 7.4.1 自定义SimpleAgent（知识点 + 整合完整代码）
## 核心知识点梳理
### 1. 继承关系
```
Agent(抽象基类) ← SimpleAgent(框架原生基础实现) ← MySimpleAgent(我们自定义扩展类)
```
- 复用顶层`Agent`自带能力：`add_message() / get_history() / _history对话存储`，不需要重复开发；
- **重写`run()`方法**，覆盖父类原生简单对话逻辑，新增**工具调用循环（简易ReAct）**；
- 扩展新方法：流式接口`stream_run()`、工具动态管理接口。

### 2. 设计思路
1. 框架原生`SimpleAgent`只实现一问一答，无工具能力；
2. 继承`SimpleAgent`做二次开发，不用从零实现Agent基础逻辑；
3. 支持两种模式自动分支：
   - 无工具模式：普通对话，直接调用LLM
   - 启用工具模式：进入多轮工具调用循环
4. 工具调用方案：**文本标记解析** `[TOOL_CALL:工具名:参数]`（非OpenAI原生function call，框架自定义格式）
5. 支持最大迭代次数限制，防止无限循环调用工具；
6. 同时提供**一次性响应 run()** 和 **流式响应 stream_run()**。

### 3. 关键流程 `run(input_text)`
1. 组装消息列表：系统提示词（自动追加工具描述）+ 历史消息 + 当前用户提问
2. 判断是否开启工具：
   - ❌ 关闭工具：直接调用`llm.invoke()`，保存对话历史，返回结果
   - ✅ 开启工具：进入`_run_with_tools`循环
3. 工具循环逻辑：
   - 请求LLM → 使用正则检测是否包含工具调用标记
   - 识别到工具调用 → 解析工具名称、参数 → 执行工具
   - 将工具结果追加进消息列表，再次交给大模型思考
   - LLM不再输出工具标记 → 返回最终答案
4. 所有问答最终存入`self._history`，维持上下文记忆

### 4. 重要方法说明
| 方法 | 作用 |
|------|------|
| `__init__` | 扩展构造函数，新增工具注册表、工具开关；`super()`调用父类初始化 |
| `run()` | 主入口，分支区分普通对话/工具对话 |
| `_get_enhanced_system_prompt` | 动态增强系统提示词，注入工具清单、调用格式 |
| `_run_with_tools` | 工具循环主逻辑 |
| `_parse_tool_calls` | 正则提取文本内的工具调用标记 |
| `_execute_tool_call` | 根据工具名执行工具 |
| `_parse_tool_parameters` | 解析工具参数字符串转为字典 |
| `stream_run` | 流式输出版本对话入口 |
| `add_tool/remove_tool/list_tools` | 动态管理工具便捷API |

# 第一份代码：my_simple_agent.py
```python
"""
自定义增强SimpleAgent
继承框架SimpleAgent，扩展工具调用、流式响应能力
"""
import re
from typing import Optional, Iterator
from hello_agents import SimpleAgent, HelloAgentsLLM, Config, Message, ToolRegistry


class MySimpleAgent(SimpleAgent):
    """
    可扩展对话智能体
    特性：基础对话 + 可选多轮工具调用 + 流式输出 + 动态工具管理
    """
    def __init__(
        self,
        name: str,
        llm: HelloAgentsLLM,
        system_prompt: Optional[str] = None,
        config: Optional[Config] = None,
        tool_registry: Optional['ToolRegistry'] = None,
        enable_tool_calling: bool = True
    ):
        # 调用父类SimpleAgent构造方法，初始化基础属性
        super().__init__(name, llm, system_prompt, config)
        # 新增工具相关成员
        self.tool_registry = tool_registry
        # 双重判断：开启开关 + 存在工具注册表才启用工具
        self.enable_tool_calling = enable_tool_calling and tool_registry is not None
        print(f"✅ {name} 初始化完成，工具调用: {'启用' if self.enable_tool_calling else '禁用'}")

    def run(self, input_text: str, max_tool_iterations: int = 3, **kwargs) -> str:
        """
        Agent主运行入口
        :param input_text: 用户输入文本
        :param max_tool_iterations: 最大工具循环次数，防止死循环
        :return: AI完整回答文本
        """
        print(f"🤖 {self.name} 正在处理: {input_text}")
        messages = []

        # 组装增强系统提示词（携带工具说明）
        enhanced_system_prompt = self._get_enhanced_system_prompt()
        messages.append({"role": "system", "content": enhanced_system_prompt})

        # 载入历史对话
        for msg in self._history:
            messages.append({"role": msg.role, "content": msg.content})

        # 追加本次用户提问
        messages.append({"role": "user", "content": input_text})

        # 分支1：不启用工具，普通对话
        if not self.enable_tool_calling:
            response = self.llm.invoke(messages, **kwargs)
            self.add_message(Message(input_text, "user"))
            self.add_message(Message(response, "assistant"))
            print(f"✅ {self.name} 响应完成")
            return response

        # 分支2：启用工具，进入工具循环逻辑
        return self._run_with_tools(messages, input_text, max_tool_iterations, **kwargs)

    def _get_enhanced_system_prompt(self) -> str:
        """构建增强系统提示词，自动追加工具清单与调用规范"""
        base_prompt = self.system_prompt or "你是一个有用的AI助手。"

        # 无工具直接返回基础提示词
        if not self.enable_tool_calling or not self.tool_registry:
            return base_prompt

        tools_description = self.tool_registry.get_tools_description()
        if not tools_description or tools_description == "暂无可用工具":
            return base_prompt

        # 拼接工具使用规则
        tools_section = "\n\n## 可用工具\n"
        tools_section += "你可以使用以下工具来帮助回答问题:\n"
        tools_section += tools_description + "\n"
        tools_section += "\n## 工具调用格式\n"
        tools_section += "当需要使用工具时，请使用以下格式:\n"
        tools_section += "`[TOOL_CALL:{tool_name}:{parameters}]`\n"
        tools_section += "例如:`[TOOL_CALL:search:Python编程]`\n\n"
        tools_section += "工具执行结果会自动提供给你，请依据结果整理最终答案。\n"
        return base_prompt + tools_section

    def _run_with_tools(self, messages: list, input_text: str, max_tool_iterations: int, **kwargs) -> str:
        """支持多轮工具调用的核心逻辑"""
        current_iteration = 0
        final_response = ""

        while current_iteration < max_tool_iterations:
            # 请求大模型
            response = self.llm.invoke(messages, **kwargs)
            # 解析是否存在工具调用标记
            tool_calls = self._parse_tool_calls(response)

            if tool_calls:
                print(f"🔧 检测到 {len(tool_calls)} 个工具调用")
                tool_results = []
                clean_response = response

                # 顺序执行全部工具
                for call in tool_calls:
                    result = self._execute_tool_call(call['tool_name'], call['parameters'])
                    tool_results.append(result)
                    clean_response = clean_response.replace(call['original'], "")

                # 将模型输出、工具结果追加进消息列表，继续对话
                messages.append({"role": "assistant", "content": clean_response})
                tool_results_text = "\n\n".join(tool_results)
                messages.append({
                    "role": "user",
                    "content": f"工具执行结果:\n{tool_results_text}\n\n请基于这些结果给出完整回答。"
                })
                current_iteration += 1
                continue

            # 没有工具调用，得到最终答案，退出循环
            final_response = response
            break

        # 达到最大循环次数依然没有最终回复，额外请求一次模型
        if current_iteration >= max_tool_iterations and not final_response:
            final_response = self.llm.invoke(messages, **kwargs)

        # 保存本轮问答到对话历史
        self.add_message(Message(input_text, "user"))
        self.add_message(Message(final_response, "assistant"))
        print(f"✅ {self.name} 响应完成")
        return final_response

    def _parse_tool_calls(self, text: str) -> list:
        """正则解析文本内 [TOOL_CALL:name:params] 格式标记"""
        pattern = r'\[TOOL_CALL:([^:]+):([^\]]+)\]'
        matches = re.findall(pattern, text)

        tool_calls = []
        for tool_name, parameters in matches:
            raw_tag = f'[TOOL_CALL:{tool_name}:{parameters}]'
            tool_calls.append({
                "tool_name": tool_name.strip(),
                "parameters": parameters.strip(),
                "original": raw_tag
            })
        return tool_calls

    def _execute_tool_call(self, tool_name: str, parameters: str) -> str:
        """执行指定工具"""
        if not self.tool_registry:
            return "❌ 错误:未配置工具注册表"
        try:
            if tool_name == "calculator":
                result = self.tool_registry.execute_tool(tool_name, parameters)
            else:
                param_dict = self._parse_tool_parameters(tool_name, parameters)
                tool = self.tool_registry.get_tool(tool_name)
                if not tool:
                    return f"❌ 错误:未找到工具 '{tool_name}'"
                result = tool.run(param_dict)
            return f"🔧 工具 {tool_name} 执行结果:\n{result}"
        except Exception as e:
            return f"❌ 工具调用失败:{str(e)}"

    def _parse_tool_parameters(self, tool_name: str, parameters: str) -> dict:
        """将参数字符串解析为参数字典"""
        param_dict = {}
        if "=" in parameters:
            if "," in parameters:
                # 多参数格式：key=value,key2=value2
                pairs = parameters.split(",")
                for pair in pairs:
                    if "=" in pair:
                        k, v = pair.split("=", 1)
                        param_dict[k.strip()] = v.strip()
            else:
                # 单参数 key=value
                k, v = parameters.split("=", 1)
                param_dict[k.strip()] = v.strip()
        else:
            # 无等号，根据工具自动封装参数
            if tool_name == "search":
                param_dict["query"] = parameters
            elif tool_name == "memory":
                param_dict["action"] = "search"
                param_dict["query"] = parameters
            else:
                param_dict["input"] = parameters
        return param_dict

    def stream_run(self, input_text: str, **kwargs) -> Iterator[str]:
        """流式对话入口，逐块返回模型输出"""
        print(f"🌊 {self.name} 开始流式处理: {input_text}")
        messages = []
        if self.system_prompt:
            messages.append({"role": "system", "content": self.system_prompt})
        for msg in self._history:
            messages.append({"role": msg.role, "content": msg.content})
        messages.append({"role": "user", "content": input_text})

        full_response = ""
        print("📝 实时响应: ", end="")
        for chunk in self.llm.stream_invoke(messages, **kwargs):
            full_response += chunk
            print(chunk, end="", flush=True)
            yield chunk
        print()

        # 流式结束后保存完整对话
        self.add_message(Message(input_text, "user"))
        self.add_message(Message(full_response, "assistant"))
        print(f"✅ {self.name} 流式响应完成")

    # ========== 工具动态管理便捷方法 ==========
    def add_tool(self, tool) -> None:
        """动态新增工具"""
        if not self.tool_registry:
            from hello_agents import ToolRegistry
            self.tool_registry = ToolRegistry()
            self.enable_tool_calling = True
        self.tool_registry.register_tool(tool)
        print(f"🔧 工具 '{tool.name}' 已添加")

    def has_tools(self) -> bool:
        """判断是否具备可用工具"""
        return self.enable_tool_calling and self.tool_registry is not None

    def remove_tool(self, tool_name: str) -> bool:
        """移除指定工具"""
        if self.tool_registry:
            self.tool_registry.unregister(tool_name)
            return True
        return False

    def list_tools(self) -> list:
        """获取全部注册工具名称"""
        if self.tool_registry:
            return self.tool_registry.list_tools()
        return []
```

# 工具基类与注册机制【重构整理：知识点 + 完整可运行代码】
## 一、核心知识点梳理
### 1. 设计目标
打造一套**统一、可扩展、双模式**的工具基础设施，给所有Agent（ReActAgent、FunctionCallAgent、SimpleAgent）提供标准化工具能力。
解决问题：
1）统一工具调用规范，不管复杂工具、简易函数，Agent调用方式一致
2）工具具备**自描述能力**：自动生成提示词描述、自动转换OpenAI FunctionCall标准Schema
3）统一中心化管理：`ToolRegistry`作为中枢，集中注册、查找、执行所有工具

### 2. 核心组件分工
|组件|作用|
| ---- | ---- |
|`Tool(ABC) 抽象基类`|定义所有标准工具强制接口；复杂自定义工具继承这个类|
|`ToolParameter`|标准化参数结构体，描述参数名称、类型、说明、是否必填（基于Pydantic，自带校验）|
|`ToolRegistry`|工具注册表（管理器）：维护工具容器，提供注册、查询、描述生成、执行入口|

### 3. 两种工具注册模式
1. **标准Tool对象模式（推荐复杂工具）**
继承`Tool`抽象类，手动实现`run()`、`get_parameters()`；支持完整参数定义、参数校验、适配FunctionCall原生协议。
2. **简易函数注册模式（快速轻量工具）**
直接注册普通Python函数，不用创建类；适合计算器、简单文本处理等轻量化场景，开发速度快。

### 4. 关键接口职责
- `run(parameters)`：统一执行入口，接收参数字典，返回字符串结果（统一输出格式，方便Agent处理）
- `get_parameters()`：工具自省，向外暴露参数结构（**自描述核心**）
- `get_tools_description()`：生成文本格式工具清单，供给ReActAgent拼接Prompt
- `to_openai_schema()`：转换成大模型Function Calling官方标准结构，供给FunctionCallAgent使用

### 5. 设计思想总结
**依赖抽象，不依赖具体实现**
Agent只和`Tool`抽象类、注册表交互，不需要关心工具内部实现；新增工具无需修改Agent代码，符合开闭原则。

## 1. 基础定义：参数模型 + Tool抽象基类
```python
from abc import ABC, abstractmethod
from typing import Any, Callable, Dict, List, Optional
from pydantic import BaseModel


class ToolParameter(BaseModel):
    """
    工具参数定义模型
    标准化描述单个入参信息，支持类型、必填项、默认值、说明
    """
    name: str               # 参数名称
    type: str               # 参数类型: string/number/integer/array/boolean
    description: str        # 参数文字说明
    required: bool = True   # 是否必填
    default: Optional[Any] = None  # 默认值


class Tool(ABC):
    """
    工具顶层抽象基类
    所有标准自定义工具必须继承该类，强制实现统一接口
    """
    def __init__(self, name: str, description: str):
        # 工具元信息：供大模型识别
        self.name: str = name
        self.description: str = description

    @abstractmethod
    def run(self, parameters: Dict[str, Any]) -> str:
        """
        执行工具逻辑
        :param parameters: 调用传入的参数字典
        :return: 字符串格式执行结果（统一返回格式，方便Agent解析）
        """
        pass

    @abstractmethod
    def get_parameters(self) -> List[ToolParameter]:
        """
        获取当前工具的参数定义列表（自省能力）
        用于生成Prompt描述、转换FunctionCall Schema、参数校验
        """
        pass

    def to_openai_schema(self) -> Dict[str, Any]:
        """
        扩展方法：将当前工具转为 OpenAI Function Calling 标准schema
        FunctionCallAgent直接调用此方法
        """
        param_list = self.get_parameters()
        properties: Dict[str, Dict[str, Any]] = {}
        required_fields: List[str] = []

        for param in param_list:
            prop_info = {
                "type": param.type,
                "description": param.description
            }
            # 追加默认值提示
            if param.default is not None:
                prop_info["description"] += f" (默认值:{param.default})"
            # 数组类型补充items定义
            if param.type == "array":
                prop_info["items"] = {"type": "string"}

            properties[param.name] = prop_info
            if param.required:
                required_fields.append(param.name)

        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": {
                    "type": "object",
                    "properties": properties,
                    "required": required_fields
                }
            }
        }
```

## 2. ToolRegistry 工具注册表（管理中枢）
```python
class ToolRegistry:
    """
    工具注册表：统一管理所有工具
    存储两类工具：标准Tool实例、简易注册函数工具
    """
    def __init__(self):
        # 容器1：标准继承Tool类的工具 {工具名称: Tool实例}
        self._tools: Dict[str, Tool] = {}
        # 容器2：简易函数工具 {工具名称: {描述, 执行函数}}
        self._functions: Dict[str, Dict[str, Any]] = {}

    def register_tool(self, tool: Tool) -> None:
        """注册标准Tool对象（复杂工具首选）"""
        tool_name = tool.name
        if tool_name in self._tools:
            print(f"⚠️ 警告:工具 '{tool_name}' 已存在，将会覆盖旧工具")
        self._tools[tool_name] = tool
        print(f"✅ 【标准工具】{tool_name} 注册成功")

    def register_function(self, name: str, description: str, func: Callable[[str], str]) -> None:
        """
        快速注册普通函数作为工具（轻量化场景）
        :param name: 工具名称
        :param description: 工具描述
        :param func: 函数，接收字符串参数，返回字符串结果
        """
        if name in self._functions:
            print(f"⚠️ 警告:函数工具 '{name}' 已存在，将会覆盖旧工具")

        self._functions[name] = {
            "description": description,
            "func": func
        }
        print(f"✅ 【函数工具】{name} 注册成功")

    def get_tools_description(self) -> str:
        """
        生成纯文本工具清单
        直接供给 ReActAgent 拼装Prompt，告诉模型可用工具
        """
        desc_list: List[str] = []
        # 遍历标准工具
        for tool in self._tools.values():
            desc_list.append(f"- {tool.name}: {tool.description}")
        # 遍历简易函数工具
        for func_name, info in self._functions.items():
            desc_list.append(f"- {func_name}: {info['description']}")

        return "\n".join(desc_list) if desc_list else "暂无可用工具"

    def get_tool(self, tool_name: str) -> Optional[Any]:
        """根据名称查找工具（标准工具/函数工具）"""
        if tool_name in self._tools:
            return self._tools[tool_name]
        if tool_name in self._functions:
            return self._functions[tool_name]
        return None

    def execute_tool(self, tool_name: str, params: Dict[str, Any]) -> str:
        """
        统一工具执行入口
        Agent调用工具的统一入口方法
        """
        # 标准Tool对象执行
        if tool_name in self._tools:
            tool = self._tools[tool_name]
            return tool.run(params)
        # 简易函数工具执行（简易模式简化，直接拼接参数字符串）
        if tool_name in self._functions:
            func = self._functions[tool_name]["func"]
            # 简易函数约定：把参数字典转为字符串传入（简易模式限制）
            arg_str = str(params)
            return func(arg_str)

        return f"错误：不存在工具 {tool_name}"
```

## 1. 两种注册模式怎么选？
✅ **继承Tool基类**：
需要多参数、参数校验、适配FunctionCall、工具逻辑复杂（文件读写、数据库查询）
✅ **register_function**：
快速原型、单参数简单脚本，不想写类，开发速度优先

# 7.5.2 自定义工具开发【知识点 + 完整注释代码】
## 核心知识点梳理
### 1. 本节方案：函数快速注册工具（`register_function`）
适用场景：简单工具、快速原型开发，不需要创建 `Tool(ABC)` 子类。
#### 优缺点
✅ 优点：代码极简，无需继承抽象类、不用实现 `run()` / `get_parameters()`
❌ 缺点：**没有结构化参数定义（无 ToolParameter）**
只能用于 **ReAct 文本模式 Agent**，无法自动生成 OpenAI FunctionCalling Schema，不能给 FunctionCallAgent 使用。

### 2. ToolRegistry.register_function 入参要求
```python
registry.register_function(
    name="工具名称",          # LLM识别工具的名字，不能重复
    description="工具功能说明",# 送入Prompt，让大模型知道什么时候调用
    func=业务函数             # 约定：接收字符串参数，返回字符串结果
)
```

### 3. 计算器工具核心设计要点
1. 使用 Python `ast` 安全解析数学表达式（不使用危险的 `eval()`）；
2. 白名单机制：只允许指定运算符、数学函数，防止代码注入；
3. 统一捕获异常，向大模型返回可读的错误文本；
4. 工厂函数 `create_calculator_registry()`：统一构建注册表，外部直接导入使用。

### 4. 整体运行流程
1. 编写纯业务函数 `my_calculate(expression:str)->str`
2. 实例化 `ToolRegistry()`
3. `register_function()` 将函数注册进注册表
4. 将 registry 交给 Agent，Agent 自动加载工具信息，LLM可调用计算器

## 完整代码（详细中文注释）

```python
import ast
import operator
import math
from hello_agents import ToolRegistry


def my_calculate(expression: str) -> str:
    """
    简单数学计算业务函数
    :param expression: 数学表达式字符串，例如 "sqrt(4)+5*2"
    :return: 计算结果 / 错误提示字符串
    """
    # 校验空输入
    if not expression.strip():
        return "计算表达式不能为空"

    # 白名单：允许的二元运算符
    operators = {
        ast.Add: operator.add,      # +
        ast.Sub: operator.sub,      # -
        ast.Mult: operator.mul,     # *
        ast.Div: operator.truediv,  # /
    }

    # 白名单：允许调用的数学函数、常量
    functions = {
        'sqrt': math.sqrt,
        'pi': math.pi,
    }

    try:
        # AST解析表达式字符串，生成抽象语法树
        node = ast.parse(expression, mode='eval')
        # 递归遍历语法树进行计算
        result = _eval_node(node.body, operators, functions)
        return str(result)
    except Exception:
        # 所有异常统一捕获，返回友好提示给大模型
        return "计算失败，请检查表达式格式"


def _eval_node(node, operators, functions):
    """
    递归遍历AST节点，执行表达式计算（内部私有函数）
    """
    # 数字常量节点
    if isinstance(node, ast.Constant):
        return node.value
    # 二元运算节点 例如 a + b
    elif isinstance(node, ast.BinOp):
        left_val = _eval_node(node.left, operators, functions)
        right_val = _eval_node(node.right, operators, functions)
        op_func = operators.get(type(node.op))
        return op_func(left_val, right_val)
    # 函数调用节点 sqrt(9)
    elif isinstance(node, ast.Call):
        func_name = node.func.id
        if func_name in functions:
            args = [_eval_node(arg, operators, functions) for arg in node.args]
            return functions[func_name](*args)
    # 名称常量 pi
    elif isinstance(node, ast.Name):
        if node.id in functions:
            return functions[node.id]
    # 无法识别的语法节点，触发外层异常捕获
    raise ValueError("不支持的表达式语法")


def create_calculator_registry() -> ToolRegistry:
    """
    工厂函数：构建并返回装载计算器工具的注册表
    外部使用：registry = create_calculator_registry()
    """
    # 实例化工具管理中枢
    registry = ToolRegistry()

    # 将计算函数注册为工具
    registry.register_function(
        name="my_calculator",
        description="简单的数学计算工具，支持基本运算(+,-,*,/)和sqrt平方根函数",
        func=my_calculate
    )

    return registry
```

# 7.5.4 工具系统高级特性【整理版：知识点 + 完整代码】
## 核心知识点总览
工具系统两大高级能力：**工具链式调用（串行依赖）**、**异步并行工具执行（无依赖并发）**

### 1）工具链式调用（ToolChain）
#### 知识点
1. **适用场景**：多个工具**存在先后依赖**，上一步结果作为下一步输入（先搜索资料，再基于资料计算）。
2. **运行逻辑**：严格顺序串行执行；依靠**全局上下文context**存储每一步输出；支持字符串模板 `{变量名}` 实现数据传递。
3. **组成**
    - `ToolChain`：定义一条流水线，新增执行步骤、执行整条链路。
    - `ToolChainManager`：多条流水线统一注册、管理、调度。
4. **特征**：必须等待上一步执行完成，才能执行下一步。

### 2）异步并行工具执行（AsyncToolExecutor）
#### 知识点
1. **适用场景**：多个工具**互相独立、无依赖**，同时执行，缩短整体耗时（一次性搜索多个关键词）。
2. **运行原理**：基于`asyncio + 线程池`；原生工具是同步函数，放到线程池运行，封装成异步接口，不阻塞主循环。
3. **特征**：任务同时启动，总耗时 ≈ 最慢工具耗时；无法互相传递结果。

### 关键对比
| 模块 | 执行方式 | 数据能否传递 | 使用场景 |
|------|--------|------------|--------|
| ToolChain 工具链 | 串行顺序执行 | ✅ 上下文传递结果 | 工具之间前后依赖 |
| AsyncToolExecutor | 并行同时执行 | ❌ 任务互相隔离 | 工具无依赖，追求速度 |

### 工具系统开发核心理念
1. **单一职责**：每个工具只负责一件事；统一接口规范。
2. **健壮性**：完善异常捕获、输入校验。
3. **性能优化**：无依赖任务使用并行执行；合理管理网络、线程资源。

## 代码一：tool_chain_manager.py（工具链）
```python
from typing import List, Dict, Any, Optional
from hello_agents import ToolRegistry


class ToolChain:
    """
    工具链：实现多工具顺序串行执行，支持步骤间数据传递
    """
    def __init__(self, name: str, description: str):
        self.name = name
        self.description = description
        self.steps: List[Dict[str, Any]] = []

    def add_step(self, tool_name: str, input_template: str, output_key: str = None):
        """
        添加执行步骤
        :param tool_name: 注册表中工具名称
        :param input_template: 输入模板，{变量名}读取上下文数据
        :param output_key: 当前步骤结果存入上下文的key，供后续步骤读取
        """
        step_key = output_key or f"step_{len(self.steps)}_result"
        self.steps.append({
            "tool_name": tool_name,
            "input_template": input_template,
            "output_key": step_key
        })

    def execute(self, registry: ToolRegistry, initial_input: str, context: Dict[str, Any] = None) -> str:
        """顺序执行整条工具链"""
        context = context or {}
        context["input"] = initial_input
        print(f"🔗 开始执行工具链: {self.name}")

        for idx, step in enumerate(self.steps, start=1):
            t_name = step["tool_name"]
            tpl = step["input_template"]
            out_key = step["output_key"]

            # 模板变量替换
            try:
                tool_input = tpl.format(**context)
            except KeyError as e:
                return f"❌ 工具链失败：缺失上下文变量 {e}"

            print(f"  步骤{idx} | 工具:{t_name} | 参数预览:{tool_input[:60]}...")
            # 调用工具注册表执行工具
            result = registry.execute_tool(t_name, tool_input)
            context[out_key] = result
            print(f"  ✅ 步骤{idx}执行完成")

        # 返回最后一步结果
        final_key = self.steps[-1]["output_key"]
        print(f"🎉 工具链 {self.name} 全部执行完毕")
        return context[final_key]


class ToolChainManager:
    """工具链管理器：统一管理多条流水线"""
    def __init__(self, registry: ToolRegistry):
        self.registry = registry
        self.chains: Dict[str, ToolChain] = {}

    def register_chain(self, chain: ToolChain):
        self.chains[chain.name] = chain
        print(f"✅ 工具链【{chain.name}】注册成功")

    def execute_chain(self, chain_name: str, input_data: str, context: Dict[str, Any] = None) -> str:
        if chain_name not in self.chains:
            return f"❌ 不存在工具链 {chain_name}"
        return self.chains[chain_name].execute(self.registry, input_data, context)

    def list_chains(self) -> List[str]:
        return list(self.chains.keys())


# 示例：创建研究工作流 搜索 → 计算
def create_research_chain() -> ToolChain:
    chain = ToolChain(
        name="research_and_calculate",
        description="搜索资料，基于搜索结果进行数值计算"
    )
    # 步骤1：搜索
    chain.add_step(
        tool_name="search",
        input_template="{input}",
        output_key="search_result"
    )
    # 步骤2：使用上一步搜索结果作为输入
    chain.add_step(
        tool_name="my_calculator",
        input_template="依据下面资料进行计算：{search_result}",
        output_key="calc_result"
    )
    return chain
```

## 代码二：async_tool_executor.py（异步并行执行器）
```python
import asyncio
import concurrent.futures
from typing import Dict, Any, List
from hello_agents import ToolRegistry


class AsyncToolExecutor:
    """
    异步工具执行器：支持并行执行多个互不依赖的工具
    底层使用线程池包装同步工具，适配asyncio事件循环
    """
    def __init__(self, registry: ToolRegistry, max_workers: int = 4):
        self.registry = registry
        # 线程池，限制最大并发数量，防止资源耗尽
        self.executor = concurrent.futures.ThreadPoolExecutor(max_workers=max_workers)

    async def execute_tool_async(self, tool_name: str, input_data: str) -> str:
        """异步执行单个工具"""
        loop = asyncio.get_event_loop()

        def sync_task():
            return self.registry.execute_tool(tool_name, input_data)

        result = await loop.run_in_executor(self.executor, sync_task)
        return result

    async def execute_tools_parallel(self, tasks: List[Dict[str, str]]) -> List[str]:
        """批量并行执行多个工具任务"""
        print(f"🚀 并行启动 {len(tasks)} 个工具任务")
        task_list = []
        for task in tasks:
            tn = task["tool_name"]
            data = task["input_data"]
            task_list.append(self.execute_tool_async(tn, data))

        # 等待所有并行任务完成
        results = await asyncio.gather(*task_list)
        print(f"✅ 全部并行任务执行结束")
        return results

    def __del__(self):
        """对象销毁时关闭线程池，释放资源"""
        if hasattr(self, "executor"):
            self.executor.shutdown(wait=True)


# 测试入口
async def test_parallel():
    registry = ToolRegistry()
    executor = AsyncToolExecutor(registry)

    task_list = [
        {"tool_name": "search", "input_data": "Python编程入门"},
        {"tool_name": "search", "input_data": "机器学习基础概念"},
        {"tool_name": "my_calculator", "input_data": "2+2"},
        {"tool_name": "my_calculator", "input_data": "sqrt(16)"}
    ]
    res_list = await executor.execute_tools_parallel(task_list)
    for index, res in enumerate(res_list):
        print(f"任务{index+1}结果：{res[:100]}...")


if __name__ == "__main__":
    asyncio.run(test_parallel())
```

## 整套工具系统层级串联（方便复习）
1. `Tool`抽象基类：定义所有正规工具统一规范
2. `SearchTool/计算器工具`：具体业务工具
3. `ToolRegistry`：工具箱，统一注册、查询、执行工具
4. `ToolChain + Manager`：编排**串行依赖工具流水线**
5. `AsyncToolExecutor`：调度**无依赖工具并发执行**
