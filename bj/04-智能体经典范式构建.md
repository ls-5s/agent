现代智能体核心价值：打通大模型推理能力与外部真实世界。
智能体可以自主理解用户需求、拆分复杂任务，调用搜索引擎、代码解释器、各类API等工具获取信息、执行动作，最终完成目标。
同时智能体存在固有局限：大模型幻觉、复杂任务下无限推理循环、工具调用格式错误、错误选择工具等，这也是智能体能力边界。

为规范智能体「思考-行动」流程，业界诞生多种经典架构。本章重点从零实现三种主流范式：
1. **ReAct（思考行动同步）**：边思考、边行动，动态根据结果调整后续方案
2. **Plan-and-Solve（先规划后执行）**：先完整生成任务执行方案，再按计划分步执行
3. **Reflection（反思型智能体）**：增加自我校验、复盘修正能力，迭代优化输出结果

### 4.1.3 基础LLM调用封装类
功能说明：
1. 自动加载.env配置；
2. 支持外部传入参数覆盖环境变量，灵活切换模型；
3. 默认开启流式输出，实时打印模型返回内容；
4. 统一异常捕获，封装网络请求错误；
5. 对外暴露简洁的`think()`方法，后续所有智能体直接复用。

```python
import os
from openai import OpenAI
from dotenv import load_dotenv
from typing import List, Dict

# 自动加载项目根目录 .env 文件
load_dotenv()

class HelloAgentsLLM:
    """
    通用LLM客户端
    适配所有OpenAI兼容接口，提供流式对话能力，作为智能体基础依赖
    """
    def __init__(
        self,
        model: str = None,
        apiKey: str = None,
        baseUrl: str = None,
        timeout: int = None
    ):
        # 优先级：函数传入参数 > 环境变量
        self.model = model or os.getenv("LLM_MODEL_ID")
        api_key = apiKey or os.getenv("LLM_API_KEY")
        base_url = baseUrl or os.getenv("LLM_BASE_URL")
        timeout = timeout or int(os.getenv("LLM_TIMEOUT", "60"))

        # 参数合法性校验
        if not all([self.model, api_key, base_url]):
            raise ValueError("缺少必要配置，请检查.env文件：模型ID、API密钥、接口地址不能为空")

        # 初始化OpenAI客户端
        self.client = OpenAI(
            api_key=api_key,
            base_url=base_url,
            timeout=timeout
        )

    def think(self, messages: List[Dict[str, str]], temperature: float = 0.0) -> str:
        """
        请求大模型，返回完整文本结果
        :param messages: 对话消息列表，标准openai消息格式
        :param temperature: 温度，越低输出越稳定，智能体场景推荐0~0.3
        :return: 模型完整字符串结果
        """
        print(f"🧠 发起调用，目标模型：{self.model}")
        try:
            stream_resp = self.client.chat.completions.create(
                model=self.model,
                messages=messages,
                temperature=temperature,
                stream=True
            )
            print("✅ 模型连接成功，接收输出：")
            content_buffer = []
            # 逐块读取流式数据
            for chunk in stream_resp:
                if not chunk.choices:
                    continue
                delta_text = chunk.choices[0].delta.content or ""
                print(delta_text, end="", flush=True)
                content_buffer.append(delta_text)
            print("\n")
            full_text = "".join(content_buffer)
            return full_text
        except Exception as err:
            print(f"❌ LLM调用异常：{err}")
            return None


# 测试入口
if __name__ == '__main__':
    try:
        llm = HelloAgentsLLM()
        msg_list = [
            {"role": "system", "content": "你是擅长编写Python代码的助手"},
            {"role": "user", "content": "实现快速排序算法"}
        ]
        print("=====开始请求模型=====")
        result = llm.think(msg_list)
        if result:
            print("=====完整返回内容=====")
            print(result)
    except ValueError as e:
        print("初始化失败：", e)
```

# Agent学习前置：ReAct 核心知识点（精简学习版，方便你吃透原理再写代码）
## 一、ReAct 是什么
全称 **Reasoning + Acting**，2022年提出，**入门智能体第一个必须掌握的范式**。
核心思想：把「思考推理」和「执行外部动作」绑定，循环运行，模仿人解决问题。

## 二、为什么需要ReAct？两大旧方案存在缺陷
1. **CoT 思维链（纯思考）**
只在模型内部推理，不能联网、不能调用工具。依赖模型静态知识库，**容易产生幻觉，无法获取实时信息**。
2. **纯行动模式**
模型直接输出调用工具指令，缺少思考过程。不知道为什么要调用工具、什么时候停止，容易乱调用工具。

> ReAct 融合两者优势：思考指导行动，行动拿到真实信息反过来修正思考。

## 三、核心循环：Thought → Action → Observation（重中之重）
1. **Thought（思考）**
智能体内在推理：分析当前信息够不够、上一步结果怎么样、下一步应该做什么。
2. **Action（行动）**
决定执行外部操作：调用搜索、计算器、API等工具。
3. **Observation（观察）**
工具执行完毕返回的真实结果，作为新信息交给大模型。

### 完整循环流程
用户问题 → LLM生成 Thought + Action → 执行Action得到Observation
把 `Thought+Action+Observation` 全部追加到对话历史
再次送入大模型，开启新一轮循环
✅ **终止条件**：Thought 中判断信息足够，不需要继续调用工具，输出最终答案

## 四、底层逻辑通俗理解
大模型不能直接接触外部世界。
ReAct 通过提示词约束输出格式，让模型显性写出思考，自主决定什么时候调用工具；
工具返回真实数据，消除模型幻觉。

## 五、适合用ReAct的任务（学习时可以用来构思测试案例）
1. 需要**实时/外部信息**：新品信息、新闻、天气
2. **精确计算**：复杂数学运算（大模型口算容易出错）
3. 对接外部系统：调用API、查询数据库

## 六、学习路线建议（结合你当前项目）
1. 掌握底层：你已经写完通用 `HelloAgentsLLM` 调用类（底座）
2. 下一步：
   - 定义通用工具抽象（Tool）
   - 编写ReAct提示词模板，强制模型输出 Thought/Action 固定格式
   - 代码解析模型输出，提取Action，执行工具
   - 循环封装，实现完整ReAct智能体
3. 跑通案例：查询「华为最新手机以及卖点」
4. 踩坑重点（写代码一定会遇到）
   - 模型不遵守格式，输出乱码，无法解析Action
   - 无限循环，不停调用工具不会终止
   - 历史上下文不断变长，token消耗上涨

## 七、关键结论（学习记忆点）
ReAct = **思考→行动→观察循环**
特点：**边想边做，动态决策下一步动作**
对比后面你要学的：
- ReAct：动态分步决策（边走边想）
- Plan-and-Solve：先一次性制定完整计划，再执行
- Reflection：执行完成后增加自我复盘修正

# 4.2.2 工具的定义与实现
大语言模型是智能体的**大脑**，**工具（Tools）** 就是智能体和外部世界交互的手脚。
ReAct智能体想要解决实时信息查询类问题，必须依靠工具获取模型知识库之外的外部信息。

本节实战目标：实现网页搜索工具，让智能体能够联网查询实时资料。
我们选用 SerpApi，封装谷歌搜索接口，可以结构化返回搜索摘要、知识图谱、答案框等高质量信息。

## 1. 环境准备
### 安装依赖库
```bash
pip install google-search-results
```
### 配置密钥
前往 SerpApi官网注册账号，获取API Key，追加到项目 `.env` 文件
```env

# 新增搜索工具密钥

```

## 2. 工具设计核心规范
一个标准工具必须包含3个要素，这是Agent开发通用规范：
1. **名称 name**：唯一标识，智能体Action中通过名称调用工具（例如`Search`）
2. **描述 description**：自然语言说明工具作用。**至关重要**，大模型依靠这段文字判断什么时候选用该工具。
3. **执行逻辑**：真正运行业务逻辑的函数，接收入参，返回结果（Observation）

## 3. 完整代码（附带详细注释）
```python
import os
from dotenv import load_dotenv
from serpapi import SerpApiClient
from typing import Dict, Any

# 加载.env环境变量
load_dotenv()

def search(query: str) -> str:
    """
    基于SerpApi实现网页搜索工具
    优先提取答案框、知识图谱；无精准答案时返回前3条搜索摘要
    :param query: 用户搜索关键词
    :return: 整理后的搜索文本结果，作为Observation提供给大模型
    """
    print(f"🔍 正在执行 [SerpApi] 网页搜索: {query}")
    try:
        # 读取密钥
        api_key = os.getenv("SERPAPI_API_KEY")
        if not api_key:
            return "错误:SERPAPI_API_KEY 未在 .env 文件中配置。"

        # 搜索请求参数
        params = {
            "engine": "google",    # 指定搜索引擎
            "q": query,            # 搜索关键词
            "api_key": api_key,
            "gl": "cn",            # 地区：中国
            "hl": "zh-cn"          # 语言：简体中文
        }

        client = SerpApiClient(params)
        results = client.get_dict()

        # 优先级1：多个答案框
        if "answer_box_list" in results:
            return "\n".join(results["answer_box_list"])
        # 优先级2：单个直接答案框
        if "answer_box" in results and "answer" in results["answer_box"]:
            return results["answer_box"]["answer"]
        # 优先级3：知识图谱简介
        if "knowledge_graph" in results and "description" in results["knowledge_graph"]:
            return results["knowledge_graph"]["description"]
        # 优先级4：普通搜索结果，取前3条摘要
        if "organic_results" in results and results["organic_results"]:
            snippets = [
                f"[{i+1}] {res.get('title', '')}\n{res.get('snippet', '')}"
                for i, res in enumerate(results["organic_results"][:3])
            ]
            return "\n\n".join(snippets)

        # 无任何搜索结果
        return f"对不起，没有找到关于 '{query}' 的信息。"

    except Exception as e:
        # 捕获网络、接口异常，把错误信息返回给模型
        return f"搜索时发生错误: {e}"


class ToolExecutor:
    """
    通用工具执行管理器
    作用：统一注册、管理、调度所有工具，支持后续扩展计算器、数据库查询等更多工具
    """
    def __init__(self):
        # 存储所有注册工具
        # key:工具名称，value: {描述,执行函数}
        self.tools: Dict[str, Dict[str, Any]] = {}

    def registerTool(self, name: str, description: str, func: callable):
        """
        注册工具
        :param name: 工具唯一名称
        :param description: 工具功能描述
        :param func: 工具执行函数
        """
        if name in self.tools:
            print(f"警告:工具 '{name}' 已存在，将被覆盖。")
        self.tools[name] = {"description": description, "func": func}
        print(f"工具 '{name}' 已注册。")

    def getTool(self, name: str) -> callable:
        """根据工具名称获取执行函数"""
        tool_info = self.tools.get(name, {})
        return tool_info.get("func")

    def getAvailableTools(self) -> str:
        """
        格式化输出所有可用工具列表
        该字符串会放进Prompt，交给大模型，让模型知道现在有哪些工具可以调用
        """
        lines = []
        for name, info in self.tools.items():
            lines.append(f"- {name}: {info['description']}")
        return "\n".join(lines)


# 测试入口：单独运行文件验证工具是否可用
if __name__ == '__main__':
    # 1. 创建工具管理器实例
    toolExecutor = ToolExecutor()

    # 2. 定义搜索工具描述，并完成注册
    search_desc = "一个网页搜索引擎。当你需要回答关于时事、事实以及在你的知识库中找不到的信息时，应使用此工具。"
    toolExecutor.registerTool("Search", search_desc, search)

    # 3. 打印全部可用工具（供给LLM识别）
    print("\n--- 可用的工具 ---")
    print(toolExecutor.getAvailableTools())

    # 4. 模拟智能体Action调用工具
    print("\n--- 执行 Action: Search['英伟达最新的GPU型号是什么'] ---")
    tool_name = "Search"
    tool_input = "英伟达最新的GPU型号是什么"

    # 获取工具函数并执行
    tool_func = toolExecutor.getTool(tool_name)
    if tool_func:
        observation = tool_func(tool_input)
        print("--- 观察 (Observation) ---")
        print(observation)
    else:
        print(f"错误:未找到名为 '{tool_name}' 的工具。")
```

## 4. 核心知识点总结
1. **工具描述非常关键**
大模型依靠工具描述判断什么时候调用工具；描述写得模糊，模型会出现不会调用工具、乱调用工具的问题。

2. **ToolExecutor工具管理器的意义**
- 统一注册工具，方便后续新增计算器、代码解释器等工具；
- `getAvailableTools()` 输出格式化文本，可以直接塞进ReAct提示词；
- 集中调度，ReAct主循环只需要依赖管理器，不用写大量if判断区分工具。

3. **工具返回值 = Observation**
工具执行完毕返回的字符串，就是ReAct循环里的观察结果，会追加到上下文历史，送入下一轮LLM。

4. **搜索结果分层解析设计目的**
优先获取答案框、知识图谱这类精准信息，减少冗余文本；
过多无关内容会浪费token，同时干扰大模型总结信息。

# 4.2.3 ReAct 智能体编码实现
## 核心知识点梳理
### 1. ReAct 智能体核心思想
ReAct = **Reason（思考） + Act（行动）**
循环流程：
`用户问题 → LLM思考(Thought) → 输出行动(Action) → 执行工具 → 获取观测Observation → 历史追加 → 下一轮思考，直到Finish输出答案`

### 2. 整体组件构成
1. **提示词模板**：约束LLM输出格式、告知可用工具、承载历史上下文，是ReAct生效关键；
2. **LLM客户端**：负责调用大模型获取文本输出；
3. **工具执行器 ToolExecutor**：统一管理、注册、调用各类外部工具（搜索、计算器等）；
4. **输出解析器**：正则提取 `Thought`、`Action`，区分「工具调用」和「Finish结束指令」；
5. **主循环 ReActAgent**：串联所有组件，设置最大步数防止无限循环。

### 3. 关键规范约束（提示词强制要求）
LLM输出固定结构：
```
Thought: 思考推理过程
Action: 指令
```
Action两种类型：
- 工具调用：`工具名[入参]` 例：`Search[华为最新手机型号]`
- 终止输出：`Finish[最终回答文本]`

### 4. 运行闭环流程
1. 组装提示词（工具列表+用户问题+历史交互）
2. 请求LLM生成Thought/Action
3. 代码解析模型输出
4. 判断Action：
   - Finish → 返回答案，终止循环
   - 工具调用 → ToolExecutor执行工具，得到Observation
5. 将 `Action + Observation` 存入历史记录
6. 未达到最大步数，进入下一轮循环

### 5. 边界保障
通过 `max_steps` 最大迭代步数作为安全阀，避免智能体无限循环调用工具。

```python
# ====================== 3. 工具执行器：统一管理所有可用工具 ======================
class ToolExecutor:
    def __init__(self):
        self.tools = {}

    def register_tool(self, name: str, func):
        """注册工具"""
        self.tools[name] = func

    def getAvailableTools(self) -> str:
        """格式化输出所有工具描述，注入提示词"""
        desc_list = []
        for name in self.tools:
            desc_list.append(f"- {name}")
        return "\n".join(desc_list)

    def getTool(self, name: str):
        """获取工具函数"""
        return self.tools.get(name)

# ====================== 4. ReAct 智能体主类 ======================
class ReActAgent:
    def __init__(self, llm_client: HelloAgentsLLM, tool_executor: ToolExecutor, max_steps: int = 5):
        self.llm_client = llm_client
        self.tool_executor = tool_executor
        self.max_steps = max_steps
        self.history = []

    def _parse_output(self, text: str):
        """解析LLM返回文本，提取 Thought 和 Action"""
        thought_match = re.search(r"Thought:\s*(.*?)(?=\nAction:|$)", text, re.DOTALL)
        action_match = re.search(r"Action:\s*(.*?)$", text, re.DOTALL)
        thought = thought_match.group(1).strip() if thought_match else None
        action = action_match.group(1).strip() if action_match else None
        return thought, action

    def _parse_action(self, action_text: str):
        """解析Action：提取工具名称、工具入参"""
        match = re.match(r"(\w+)\[(.*)\]", action_text, re.DOTALL)
        if match:
            return match.group(1), match.group(2)
        return None, None

    def run(self, question: str):
        """智能体执行入口，主循环"""
        self.history = []
        current_step = 0

        while current_step < self.max_steps:
            current_step += 1
            print(f"\n--- 第 {current_step} 步 ---")

            # 1. 拼装提示词
            tools_desc = self.tool_executor.getAvailableTools()
            history_str = "\n".join(self.history)
            prompt = REACT_PROMPT_TEMPLATE.format(
                tools=tools_desc,
                question=question,
                history=history_str
            )

            messages = [{"role": "user", "content": prompt}]
            # 2. 调用LLM
            response_text = self.llm_client.think(messages=messages)
            if not response_text:
                print("错误: LLM未能返回有效响应。")
                break

            # 3. 解析模型输出
            thought, action = self._parse_output(response_text)
            if thought:
                print(f"🤔 思考: {thought}")
            if not action:
                print("警告:未能解析出有效的Action，流程终止。")
                break

            # 4. 判断动作类型
            if action.startswith("Finish"):
                match_res = re.match(r"Finish\[(.*)\]", action, re.DOTALL)
                final_answer = match_res.group(1) if match_res else "无答案"
                print(f"🎉 最终答案: {final_answer}")
                return final_answer

            # 工具调用分支
            tool_name, tool_input = self._parse_action(action)
            if not tool_name or not tool_input:
                print(f"⚠️ Action格式非法：{action}")
                continue
            print(f"🎬 行动: {tool_name}[{tool_input}]")

            # 执行工具
            tool_func = self.tool_executor.getTool(tool_name)
            if not tool_func:
                observation = f"错误:未找到名为 '{tool_name}' 的工具。"
            else:
                observation = tool_func(tool_input)
            print(f"👀 观察: {observation}")

            # 5. 本轮行动与观测存入历史，带入下一轮上下文
            self.history.append(f"Action: {action}")
            self.history.append(f"Observation: {observation}")

        # 达到最大步数退出
        print(f"\n已达到最大步数{self.max_steps}，流程终止。")
        return None
```

# 4.2.4 ReAct 核心要点提炼
## 一、核心特点
1. **高可解释性**：Thought 链路透明，可直观查看智能体每一步思考与工具选择逻辑，便于调试。
2. **动态规划、支持纠错**：步进式执行（走一步看一步），依据工具返回的 Observation 动态调整后续方案，可修正上一步错误操作。
3. **LLM+外部工具协同**：大模型负责推理规划，工具完成搜索、计算等任务，弥补大模型知识滞后、运算不准的短板。

## 二、固有局限性
1. **强依赖底层LLM能力**：推理、指令遵守、格式化输出能力不足会造成规划错误、输出格式异常，流程中断。
2. **执行效率偏低**：串行多轮调用大模型，复杂任务耗时、Token成本更高。
3. **提示词具备脆弱性**：运行依赖精心设计的Prompt，措辞改动易影响行为；部分模型难以稳定遵守输出格式。
4. **易陷入局部最优/循环**：缺少全局长远规划，容易选择短期可行、长期较差的路径，甚至重复无效操作。

## 三、调试技巧
1. 打印完整Prompt（携带全部历史上下文），溯源决策问题；
2. 输出大模型原始返回文本，区分是模型格式违规还是代码解析逻辑bug；
3. 校验工具入参格式、工具返回Observation是否符合Agent读取规范；
4. 增加Few-shot样例，提供标准Thought-Action-Observation示范；
5. 更换更强模型；调低temperature（常用0），提升输出稳定性。

# Agent学习专用 · Plan-and-Solve 浓缩笔记
（面向智能体开发、面试、框架理解，剔除论文数学符号，聚焦Agent工程视角）
## 一、核心定位
PaS（Plan-and-Solve）是**Agent推理范式之一**，2023年提出；解决：长序列任务中LLM容易步骤跑偏、遗忘目标的问题。

对比记忆（重中之重）
1. **ReAct（反应式）**
循环：思考 → 行动 → 观测
特点：走一步看一步，动态调整，**没有全局完整方案**。适合未知环境、需要持续根据反馈改变策略。
2. **Plan-and-Solve（预规划式）**
流程：**一次性全局规划 → 顺序执行所有步骤**
特点：开工前产出完整任务蓝图，后续严格依照计划执行。

比喻巩固
- ReAct：野外探险，边走边探路
- Plan-and-Solve：旅游前做好完整行程表，按表游玩

## 二、两阶段完整Agent运行流程
### 阶段1：规划 Planning
输入：用户原始任务
行为：**不执行任何工具、不计算、不操作**
LLM负责：把大任务拆解成有序步骤清单（全局计划）
输出：步骤列表 Plan = [步骤1，步骤2，步骤3……]

### 阶段2：执行 Solve
输入：原始任务 + 完整计划 + 历史执行结果
行为：按顺序逐条执行计划内任务
每一步可以：调用工具、运算、文本处理；
执行过程**原生PaS不会修改最初计划**
持续执行直到计划全部完成，输出最终答案

## 三、原生PaS优缺点（Agent开发选型必看）
✅ 优势
1. 长链条复杂任务，目标稳定，不容易中途迷失方向
2. 步骤清晰，方便日志记录、人工审查Agent行为
3. 天然适合结构化、确定性任务

❌ 原生缺陷
1. **缺乏动态调整能力**：计划写错/外部环境变化，Agent依旧硬着头皮执行；
2. 任务高度不确定时，提前写出完美全局计划难度很大。

> 工程改良方案：**带重规划的Plan-and-Solve**
> 执行遇到阻碍时，触发重新规划（工业Agent经常使用）

## 四、Agent适合/不适合场景
✅ 优先选Plan-and-Solve
1. 数学多步推理
2. 报告撰写、文档整理（结构固定）
3. 代码开发：先架构设计，再逐模块编码
4. 已知信息充足、流程可提前预判的自动化任务

❌ 优先选ReAct，不要原生PaS
1. 开放式搜索（不知道会查到什么信息）
2. 人机博弈、动态环境交互
3. 需要根据实时观测不断变更思路的任务

## 五、面试高频区分题标准答案
Q：ReAct 和 Plan-and-Solve 最大区别？
A：
ReAct属于增量式局部决策，每一轮根据最新观测即时思考行动，不存在预先完整全局方案；
Plan-and-Solve 将流程解耦，先一次性生成全局完整行动计划，之后按顺序分步执行。

## 六、拓展（工程结合思路）
现实开发Agent不会死板二选一：
很多成熟智能体框架融合两种思想：
先用PaS生成初步计划 → 执行过程中利用类似ReAct的反馈机制，必要时重新规划。

## 极简背诵版（快速复盘）
Plan-and-Solve = 先全局规划，后顺序执行。
和走一步看一步的ReAct形成互补；
优点是长任务不易偏离目标；原生短板是缺少动态调整；
适合结构明确、可提前拆解的任务。

# 4.3.2 规划阶段 | 重点总结 + 规范格式化代码
## 一、核心重点总结
### 1. 实验思路
依托**无工具、纯提示词**方案演示原生 Plan-and-Solve（PaS）；
适用任务：无法一次性求解，需要拆解为有序子步骤，完美匹配「先规划，后执行」范式。

### 2. 两段式核心流程
1. **规划阶段**：LLM仅负责任务拆解，不开展任何计算；输出结构化、程序可解析的步骤清单
2. **执行阶段（后续拓展）**：顺序执行每一步计划，能够复用前面步骤产出的中间结果

演示案例：水果店三日苹果销量求和数学应用题

### 3. 提示词三大设计要点（核心考点）
1. **角色设定**：定义AI为规划专家，引导模型目标聚焦任务拆分
2. **任务约束**：拆分得到独立、有序、可落地执行的子任务
3. **强格式约束**：强制使用 ```python ``` 包裹输出标准Python列表
> 核心价值：规避自由文本输出；标准化格式便于程序自动解析，提升系统稳定性。

### 4. Planner规划器内部执行流程
1. 接收用户原始问题，填充预设提示词模板
2. 调用LLM获取返回文本
3. 字符串切片截取代码标记内的列表文本
4. 使用 `ast.literal_eval()` **安全将字符串转为列表**（禁止eval()，存在代码注入风险）
5. 完备异常捕获，解析失败返回空列表，防止程序直接崩溃

### 5. 核心设计思想
**规划逻辑与执行逻辑解耦**：Planner只负责生成行动计划，不参与任务运算；生成的计划可以交由独立执行器处理。

        except (ValueError, SyntaxError, IndexError) as e:
            print(f"❌ 计划解析异常: {e}")
            print(f"原始响应内容: {response_text}")
            return []
        except Exception as e:

# 4.3.3 执行器与状态管理
规划器（Planner）输出任务拆解方案后，需要**执行器（Executor）**逐条落地计划内的子任务。
执行器两大核心职责：
1. 调用大模型完成每一个子任务；
2. **状态管理**：持久保存每一步运行结果，把历史上下文持续传递给后续任务，保证整条任务链路信息连贯。

执行器提示词和规划器有着明确分工：规划器负责拆分问题，执行器聚焦**完成当前单个子步骤**。
因此执行器Prompt必须携带四类上下文信息：
- 原始问题：锚定最终目标，防止模型偏离主线；
- 完整计划：让模型知晓当前步骤在全局任务中的位置；
- 历史步骤与结果：过往所有执行输出，作为当前步骤的输入上下文；
- 当前步骤：明确本次需要完成的具体任务。

```python
EXECUTOR_PROMPT_TEMPLATE = """
```

### 4.4.1 Reflection 机制的核心思想

**思想来源：** Reflection（反思）机制借鉴人类思考习惯：写完文稿会校对、算出题目会验算，依靠自我审查修正错误。代表性工作为2023年Shinn, Noah提出的 Reflexion 框架。整套机制核心是持续迭代循环：**执行 → 反思 → 优化**。

**三步循环解析：**

**1. 执行 Execution**
智能体依托基础范式（ReAct / Plan-and-Solve）完成任务，产出初步方案、推理轨迹或答案，相当于产出一份**初稿**。

**2. 反思 Reflection**
启用独立LLM（专用提示词）充当评审者，对初稿全方位审查，重点核查四类问题：
- 事实错误：结论违背常识、客观信息；
- 逻辑漏洞：推理链条断裂、前后自相矛盾；
- 效率缺陷：方案步骤冗余，存在更简洁可行路径；
- 信息遗漏：忽略题目约束、关键条件。
审查完成后输出**结构化反馈Feedback**，清晰写明问题位置、错误原因与改进方向。

**3. 优化 Refinement**
把原始任务、上一版初稿、反思得到的反馈一同作为上下文输入大模型，指导模型根据反馈修正缺陷，生成改良后的**修订稿**。

> 循环规则：重复「执行-反思-优化」流程。直至反思阶段找不到新问题，或达到最大迭代次数，终止循环。

**核心价值（对比原生PaS、ReAct）：**

1. **内置内部纠错环路**：不再单纯依赖外部工具返回的观测信息（ReAct 的 Observation），能够自主发现高层逻辑、策略层面的错误，实现自我修正。
2. **任务迭代优化**：把单次执行升级为多次迭代打磨，大幅提升复杂推理任务的正确率与输出质量。
3. **构建短期经验记忆**：全部迭代轨迹（执行记录、反思意见、修改过程）构成短期记忆。智能体不仅持有最终答案，同时完整保留”从错误版本迭代至正确版本”的全过程。该机制还可拓展至多模态场景，支持对代码、图像等非文本结果反思修正。

**极简考点背诵版：** Reflection 基于人类自查验算思维，核心循环为**执行-反思-优化**。先由智能体产出初始方案；独立评审模型检查缺陷并生成反馈；模型结合反馈迭代优化方案，循环直至收敛。它提供内部自纠错能力，形成迭代优化链路，同时留存推理迭代记忆，弥补PaS、ReAct原生缺少自我审查的短板。


# 4.4.2 案例设定与记忆模块设计
为直观落地 Reflection 机制，我们引入记忆管理组件。Reflection依托历史信息完成存储与提取；若直接把全部交互内容送入评审模型进行反思，上下文会充斥大量冗余信息，造成资源浪费。本次实战目标为**代码生成与迭代优化**。

本次任务：编写Python函数，筛选出1~n范围内所有素数。
该任务十分适合验证Reflection机制，理由如下：
1. 存在清晰的优化路径：大模型初次生成代码大概率为逻辑简单，但执行效率较低的递归方案；
2. 反思切入点明确：评审模块能够识别代码时间复杂度高、存在大量重复运算等缺陷；
3. 优化方向清晰：结合反思反馈，可迭代改造为高效迭代实现，或是引入备忘录优化方案。

Reflection的核心是持续迭代，而迭代的基础是智能体能够记录过往尝试与反思反馈。因此必须搭建**短期记忆模块**，用来持久保存每一轮「执行-反思」完整轨迹。

```python
from typing import List, Dict, Any, Optional

class Memory:
    """
    简易短期记忆模块，存储智能体执行记录与反思轨迹
    """
    def __init__(self):
        """初始化空容器，存放所有记忆记录"""
        self.records: List[Dict[str, Any]] = []

    def add_record(self, record_type: str, content: str):
        """
        新增一条记忆记录
        参数：
        record_type：记录类型，可选 'execution'(执行输出) / 'reflection'(反思反馈)
        content：记录具体内容，例如生成的代码、反思评审意见
        """
        record = {"type": record_type, "content": content}
        self.records.append(record)
        print(f"📝 记忆已更新，新增一条 '{record_type}' 记录。")

    def get_trajectory(self) -> str:
        """
        将全部记忆记录拼接为完整文本，直接嵌入提示词
        为模型反思、方案迭代提供完整上下文
        """
        trajectory_parts = []
        for record in self.records:
            if record['type'] == 'execution':
                trajectory_parts.append(f"--- 上一轮尝试(代码) ---\n{record['content']}")
            elif record['type'] == 'reflection':
                trajectory_parts.append(f"--- 评审员反馈 ---\n{record['content']}")
        return "\n\n".join(trajectory_parts)

    def get_last_execution(self) -> Optional[str]:
        """
        获取最新一轮执行输出（最新生成代码）
        若无执行记录，则返回None
        """
        # 倒序遍历，快速找到最近一次执行结果
        for record in reversed(self.records):
            if record['type'] == 'execution':
                return record['content']
        return None
```

## Memory类设计解析
整个模块结构简洁，核心设计思路如下：
1. 使用列表`records`有序保存所有执行、反思记录；
2. `add_record`：对外提供接口，追加新的轨迹信息；
3. `get_trajectory`：模块核心方法，将结构化记忆序列化为文本字符串，直接填充进Prompt，给模型提供完整历史上下文；
4. `get_last_execution`：便捷工具方法，快速读取最新一轮执行产出，供反思模块调用。

## 考点精简总结
短期记忆模块是Reflection智能体必备组件，用于保存多轮迭代的执行结果与反思反馈；它可以统一格式化历史轨迹，为反思评审、下一轮优化迭代提供上下文支撑，避免重复信息冗余输入。

```python
class ReflectionAgent:
    """
    基于Reflection范式的代码迭代智能体
    运行循环：初始执行 -> [反思评审 -> 代码优化] 循环
    """
    def __init__(self, llm_client, max_iterations: int = 3):
        """
        :param llm_client: 大模型调用客户端实例
        :param max_iterations: 最大反思优化轮次
        """
        self.llm_client = llm_client
        self.memory = Memory()          # 存储每一轮代码、反思记录
        self.max_iterations = max_iterations

    def run(self, task: str) -> str:
        """
        智能体入口方法，启动完整执行-反思-优化流程
        :param task: 代码编写任务描述
        :return: 迭代完成后的最终代码
        """
        print(f"\n========== 启动Reflection智能体 ==========")
        print(f"任务内容：{task}")

        # 阶段1：首次执行，生成初始版本代码
        print("\n[阶段1] 生成初始代码")
        initial_prompt = INITIAL_PROMPT_TEMPLATE.format(task=task)
        initial_code = self._call_llm(initial_prompt)
        self.memory.add_record(record_type="execution", content=initial_code)

        # 阶段2：迭代循环：反思评审 + 代码优化
        for loop_idx in range(self.max_iterations):
            current_round = loop_idx + 1
            print(f"\n[阶段2] 第 {current_round}/{self.max_iterations} 轮迭代")

            # ① 获取最新代码，启动反思评审
            latest_code = self.memory.get_last_execution()
            print("--> 执行代码反思评审")
            reflect_prompt = REFLECT_PROMPT_TEMPLATE.format(task=task, code=latest_code)
            review_feedback = self._call_llm(reflect_prompt)
            self.memory.add_record(record_type="reflection", content=review_feedback)

            # ② 终止条件：评审判定无需继续优化，跳出循环
            if "无需改进" in review_feedback:
                print("✅ 评审结论：代码已达到最优，停止迭代")
                break

            print("--> 根据评审反馈优化代码")
            refine_prompt = REFINE_PROMPT_TEMPLATE.format(
                task=task,
                last_code_attempt=latest_code,
                feedback=review_feedback
            )
            new_code = self._call_llm(refine_prompt)
            self.memory.add_record(record_type="execution", content=new_code)

        # 读取记忆中最后一版代码作为结果返回
        final_code = self.memory.get_last_execution()
        print(f"\n========== 任务结束 ==========")
        print("最终生成代码：")
        print(f"```python\n{final_code}\n```")

        """
        messages = [{"role": "user", "content": prompt}]
        response = self.llm_client.think(messages=messages)
        return response if response is not None else ""
```

```python
from typing import List, Dict, Any


class Memory:
    """短期记忆模块，保存智能体所有执行记录与反思记录"""
    def __init__(self):
        self.records: List[Dict[str, Any]] = []

    def add_record(self, record_type: str, content: str):
        """新增一条记忆记录"""
        self.records.append({
            "type": record_type,
            "content": content
        })

    def get_last_execution(self) -> str:
        """获取最近一次生成的代码（execution类型记录）"""
        # 倒序查找最新代码记录
        for item in reversed(self.records):
            if item["type"] == "execution":
                return item["content"]
        return ""
```

```python
def find_primes(n):
    """
    Finds all prime numbers between 1 and n using the Sieve of Eratosthenes algorithm.

    :param n: The upper limit of the range to find prime numbers.
    :return: A list of all prime numbers between 1 and n.
    """
    if n < 2:
        return []

    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False

    p = 2
    while p * p <= n:
        if is_prime[p]:
            for i in range(p * p, n + 1, p):
                is_prime[i] = False
        p += 1

    primes = [num for num in range(2, n + 1) if is_prime[num]]
    return primes
```
