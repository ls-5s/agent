# 第三章 大语言模型基础
Transformer、提示、主流 LLM 及其局限

# 3.1.1 从N-gram到RNN｜核心重点精简总结
适合你**Agent应用开发方向**，剔除公式演算细节，只保留需要理解、面试有用、帮助看懂Transformer的核心内容。
## 主线进化链条
**N-gram（统计语言模型） → 神经网络语言模型（词嵌入） → RNN → LSTM**
每一代都是为了解决上一代的短板，这条演进脉络是重中之重。

## 一、N-gram（统计语言模型）
1. **核心目标**：语言模型本质任务——计算句子出现概率，实现「预测下一个词」。
2. **核心假设：马尔可夫假设**
不用看全部上文，只依靠**前面有限n-1个词**预测当前词。
    - Bigram(N=2)：只看前1个词
    - Trigram(N=3)：只看前2个词
3. **计算方式**：纯统计计数，通过语料词频估算条件概率。
4. **两大致命缺陷（必须记住）**
    ✅ **数据稀疏**：没有在语料出现过的词语组合，概率直接为0；平滑手段只能缓解，无法根除。
    ✅ **无泛化能力**：单词只是孤立符号，**不能理解语义相似度**。分不清`agent`和`robot`含义相近。

> 学习取舍：看懂思想，**不用手动刷题演算概率公式**。

## 二、神经网络语言模型 + 词嵌入 Word Embedding
### 解决了N-gram最大痛点：离散符号没有语义
1. **词嵌入核心思想**
把单词映射为**高维连续向量**；语义相近的词，向量在空间距离更近。
2. **度量工具：余弦相似度**
用来衡量两个词向量之间语义相似程度。
3. **经典案例**
`vector(king) - vector(man) + vector(woman) ≈ vector(queen)`
证明词向量可以学习到抽象语义关系。
4. **遗留局限**
依然是**固定上下文窗口**，只能读取前面固定数量单词，无法处理更长距离文本。

> ⭐本节最高价值知识点！后续RAG向量检索、LLM内部全部建立在词向量思想之上，一定要吃透。

## 三、RNN 循环神经网络
1. **诞生目的**：打破「固定上下文窗口」限制，给模型增加**记忆能力**。
2. **原理**
引入**隐藏状态（hidden state）**充当短期记忆；逐词顺序处理文本，不断把上一步记忆传递到下一步。
3. **原生RNN致命问题：长期依赖问题**
    - 训练时梯度不断连乘，出现**梯度消失/梯度爆炸**；
    - 文本一长，模型就丢失很早之前的信息；
    - **串行计算**，无法并行训练，训练速度很慢。

## 四、LSTM（改良版RNN）
1. **目标**：缓解标准RNN梯度消失、长距离记忆失效问题。
2. **核心创新**
新增**细胞状态Cell State**（长期信息通道）+ **三套门控机制**（信息阀门）：
    - 遗忘门：丢弃过时信息
    - 输入门：存入新信息
    - 输出门：决定对外输出哪些记忆
3. **局限**
只是缓解长依赖，没有彻底根除；**依旧串行运算，训练效率低下**。

# 整体一句话串联考点
N-gram靠统计计数，不懂语义；词嵌入把单词转为向量，获得语义泛化能力，但窗口固定；RNN引入记忆支持变长文本，但是长文本梯度消失、只能串行；LSTM利用门控改善记忆缺陷，但依然摆脱不了串行低效。
→ **最终催生Transformer自注意力机制，彻底解决串行瓶颈！**

## 一、开篇总览（最高优先级）
1. **Transformer诞生的核心意义**
RNN/LSTM串行逐词计算，**无法并行训练**，训练速度慢；
Transformer 2017年《Attention Is All You Need》，**彻底抛弃循环结构，依靠注意力机制，实现全局并行计算**。

2. **原始架构：Encoder-Decoder（编码器-解码器），最初为机器翻译设计**
- Encoder（编码器）：**理解输入完整句子**，双向自注意力，可以看见全部输入文本；
- Decoder（解码器）：**逐一生成目标句子**；一边看自己已经生成的内容，一边读取Encoder的理解结果。

> 铺垫：后续GPT只用Decoder（Decoder-Only）；BERT只用Encoder（Encoder-Only）。

## 二、三大注意力机制（重中之重，必考区分）
### 1. 缩放点积自注意力 Self-Attention
核心逻辑：每个词元生成 **Q查询、K键、V值**
公式：
$$\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$
通俗理解：
Q=当前词提问；K=所有词的索引；V=所有词携带信息
1. Q和K点积，算出词语之间相关性；
2. **除以$\sqrt{d_k}$缩放**：防止维度大时点积数值爆炸，避免softmax梯度消失；
3. softmax转为权重；
4. 权重 × V 求和，得到融合全局上下文的新词向量。

### 2. 多头注意力 Multi-Head Attention
- 操作：把Q/K/V切分成多组，每组独立做自注意力，最后拼接融合；
- 作用：让多个"专家"**从不同角度捕捉多种语义关系（指代、语法、时序）**，提升表达能力。

### 3. 三种注意力分清（极易混淆）
1. **Encoder：普通自注意力**
QKV来自同一输入序列；双向，能看到句子全部词语。
2. **Decoder第一层：掩码自注意力（Masked Self-Attention / 因果注意力）**
❌ 禁止看到未来还未生成的词；通过mask把未来位置分值设为极小负数，softmax后权重=0，防止"作弊"。
3. **Decoder第二层：交叉注意力 Cross-Attention**
Q来自Decoder（正在生成的文本）；K、V来自Encoder输出；
作用：生成文字时，去参考原输入句子信息（机器翻译：译文参考原文）。

## 三、EncoderLayer 编码器层结构（两层子层）
每层固定顺序：
多头自注意力 → Add & Norm → 逐位置前馈网络FFN → Add & Norm
1. 多头自注意力：序列内部词语互相交换信息
2. Position-Wise FFN（逐位置前馈网络）
特点：**独立作用于每一个词元，所有位置共享同一套权重**
作用：对单个词向量做非线性特征提取
结构：Linear → ReLU → Linear（先升维d_ff=4*d_model，再降维）

## 四、DecoderLayer 解码器层结构（三层子层）
掩码多头自注意力 → Add&Norm
→ 交叉多头注意力 → Add&Norm
→ FFN前馈网络 → Add&Norm

## 五、Add & Norm：残差连接 + 层归一化（必须记住作用）
1. **残差连接 Add：$x+\text{Sublayer}(x)$**
梯度可以直接沿残差通路传播，**缓解深度模型梯度消失**。
2. **层归一化 Norm（Layer Norm）**
对单条样本内部特征归一化，稳定每层输入分布，加速收敛。

## 六、位置编码 Positional Encoding【高频考点】
致命问题：自注意力本身**不感知词语顺序**，调换词语顺序模型认为几乎一样。
解决方案：位置编码
- 将位置信息编码成向量，**加到词嵌入向量上**；
- 原文使用正弦余弦函数生成固定位置编码；
- 作用：让模型区分词语先后顺序。

## 七、整条知识链路串联（巩固你前面所有内容）
N-gram（统计，无语义、固定窗口）
→ Word2Vec（静态词向量，一词多义无法区分、固定窗口）
→ RNN（串行、梯度消失）→ LSTM（缓解梯度消失，依旧串行）
👉 **Transformer：抛弃循环、并行计算、全局注意力、动态上下文向量**
→ 衍生三大架构：Encoder-Only(BERT)、Encoder-Decoder(T5)、Decoder-Only(GPT/LLaMA)

# 自测3道核心考题（检验是否掌握）
1. Transformer对比RNN/LSTM最大优势是什么？
答：摒弃循环结构，依靠注意力机制，支持并行计算；可以直接捕捉全局长距离依赖。

2. Decoder里掩码自注意力mask的作用？
答：屏蔽未来位置词元，生成时只能利用前文信息，防止信息泄露。

3. 为什么需要位置编码？
答：自注意力机制没有内置时序信息，无法识别词元先后顺序；位置编码注入位置信息。

# 大白话完整梳理 Decoder-Only（GPT、Llama 这类大模型的架构）
## 一、先分清原版完整Transformer vs Decoder-Only
原始Transformer = Encoder编码器 + Decoder解码器，定位**翻译任务**
逻辑：编码器读完原文理解全文 → 解码器对照原文逐字输出译文（先理解、再生成）

GPT团队思考：
做聊天、写文章、续写内容，根本不需要单独的编码器。
所有任务本质都是**文字接龙：根据前面的文字，预测下一个字**。
于是直接删掉整个Encoder，**只保留堆叠多层的解码器模块** → 这就是Decoder-Only架构。

> 注意：它用的解码器模块，**去掉了解码器里独有的【交叉注意力】**，只保留【掩码多头自注意力 + FFN】

## 二、什么是「自回归 Autoregressive」
超级通俗理解：文字接龙
输入：`今天周末，我打算`
1. 模型算出下一个词：`出去玩`
2. 把新词拼到末尾，新输入变成：`今天周末，我打算出去玩`
3. 再基于新文本继续预测下一个词
循环往复，直到生成结束符号，停止输出。

每一步的输出，都会变成下一步的输入，这个过程就叫自回归。

## 三、核心关键：因果掩码（掩码自注意力）
### 解决的问题：训练不许"偷看答案"
训练的时候，完整一句话一次性喂进模型。
如果没有掩码，句子后面的文字会直接被前面的单词看到，模型直接作弊，不需要学习预测。

掩码操作规则：
限制第`t`个单词，**只能看见自己以及前面所有文字，看不见后方未来的文字**。
数学实现：把后面位置的注意力分值设置成负无穷，经过softmax之后权重直接等于0，彻底屏蔽未来信息。

👉核心目的：**训练模式 和 真实对话生成模式保持统一**
训练、推理两套规则一致，模型效果才会好。

## 四、Decoder-Only 三大优势（面试背诵要点）
1. **训练目标统一**
全部任务简化为【预测下一个token】，可以使用互联网海量无标签文本预训练，不需要人工标注数据。
2. **结构简洁、方便做大模型**
没有编码器、没有交叉注意力，组件更少；容易不断堆层数、扩大参数规模。GPT系列、Llama、Qwen通义千问底层全部是这套架构。
3. **天生适配生成任务**
对话、写文案、写代码、续写文本全部都是自回归任务，完美匹配文字接龙的模式，适合用来做聊天大模型、AI智能体大脑。

## 五、精简面试背诵版本（直接记）
Decoder-Only架构舍弃了原始Transformer的编码器，仅由多层改造后的解码器堆叠而成，GPT、Llama等主流大模型均采用该结构。
它采用自回归模式工作：不断根据已有文本预测下一个词，并把生成内容并入上下文继续预测。
依靠**因果掩码（掩码自注意力）**，保证模型无法看到当前位置之后的token，防止训练阶段偷看未来信息，保证训练和推理逻辑一致。
优势：训练目标统一，可利用海量无标注数据预训练；架构简单易于大规模拓展；天然适配文本生成、对话类任务。

## 补充一个易混小考点
原始Decoder拥有三层：掩码自注意力 → 交叉注意力 → FFN
Decoder-Only里面的单层结构只有两层：**掩码自注意力 + FFN**
交叉注意力被彻底移除，不存在编码器供它读取信息！

# 3.2 与大语言模型交互 —— 提示工程【核心总结】
## 一、基础定义
提示(Prompt)是人与大模型沟通的载体；**提示工程**：设计精准提示词，引导模型输出预期结果，在Agent开发中直接影响智能体任务执行、多智能体协作效率。

## （1）模型采样参数（解码阶段控制输出风格）
底层原理：模型通过Softmax得到各token概率，采样参数修改概率分布/筛选候选token，决定下一个生成词汇。
1. **Temperature（温度）**
修改全局概率分布陡峭程度
- $0 \le T<0.3$：分布陡峭，输出确定、严谨；适合代码、计算、事实问答、技术文档
- $0.3 \le T<0.7$：平衡性自然；日常对话、普通文案
- $0.7 \le T<2$：分布平缓，增加随机性；创意写作、头脑风暴
> T=0：退化为贪心采样，只选择概率最高token，Top-k/Top-p失效

2. **Top-k采样**
将token按概率排序，**固定保留前k个候选**，再概率归一化采样；
k=1等价贪心采样；缺点：固定数量，无法适配不均匀概率分布。

3. **Top-p（核采样）**
动态筛选：按概率累加token，直到累积概率≥p，取这组token作为候选集；
优势：候选数量动态变化，适配不同概率分布，工业更常用。

4. 参数协同规则
执行优先级：**温度调整 → Top-k → Top-p**
实践建议：Top-k、Top-p**二选一**；温度为0或k=1时，其余采样参数无效。

> Agent开发经验：工具调用、数据查询、任务规划建议**低温**，减少幻觉与无效工具调用。

## （2）零样本 / 单样本 / 少样本提示（上下文学习ICL）
依靠预训练能力，**无需微调，仅在prompt内提供示例**让模型理解任务：
1. **Zero-shot 零样本**：不提供样例，直接下发指令；适合简单、模型熟悉的通用任务。
2. **One-shot 单样本**：提供1组输入输出示范，教会模型输出格式。
3. **Few-shot 少样本**：提供多组多样化示例；适合结构化输出、规则复杂、边界清晰的任务。
> Agent场景常用：少样本约束输出JSON格式、规范思考+工具调用格式。

## （3）指令调优（Instruction Tuning）影响
- 原始预训练模型：文本续写模型，擅长补全文本，很难听懂人类指令，高度依赖少样本。
- **指令调优**：使用大量「指令-答案」数据微调；模型学会遵循自然语言指令。
现今商用大模型（Qwen、DeepSeek、GPT系列）均经过指令调优，支持直接自然语言下发任务，大幅降低提示编写难度。

## （4）基础提示工程实用技巧
1. **角色扮演**：赋予模型明确身份，约束回答知识范围、语气风格；广泛用于Agent系统提示词。
2. **上下文样例**：即少样本思想，强制统一输出结构（JSON、固定格式），解决模型输出混乱问题。

## （5）思维链 CoT（Chain-of-Thought）
面向多步骤逻辑推理、数学计算、复杂决策任务。
技巧：提示增加引导语「逐步思考」，迫使模型显式输出推理步骤。
收益：降低推理错误，便于人工校验，是推理型Agent核心提示手段。

# 核心重点总结（适配Agent应用开发，不用深挖算法底层）
## 一、核心概念
**Tokenization（分词/词元化）**
文本 → Token（词元） → 数字ID
大模型**不能直接读文字，只能处理数字**，分词器就是做这个转换的工具。

三种分词方案对比：
1. **基于单词分词**
缺点：词表爆炸、大量未登录词OOV；变形单词（look/looks/looking）被当成无关token。
2. **基于字符分词**
缺点：单个字符语义弱，模型学习成本极高，效率差。
3. **子词分词（现在所有大模型通用）**
✅ 平衡方案：常见词完整保留；生僻词拆成有意义片段。
解决OOV问题，同时控制词表规模。

## 二、主流子词算法区分（记住特点即可）
1. **BPE（字节对编码，GPT系列）**
训练规则：不断合并**出现频率最高**的相邻词元对。
2. **WordPiece（BERT）**
不看单纯频率，优先选择合并后**整体语言概率提升最大**的组合。
3. **SentencePiece（Llama、很多开源模型）**
把空格当作普通字符；**无需预先分词，天然支持中文、日文等无分隔语言**，编码解码可逆。

> 你不用手写BPE训练代码，看懂代码演示流程、理解“高频片段不断合并”逻辑足够。

## 三、【重中之重】分词器对你（Agent开发者）的实际影响
1. **上下文窗口限额 = 按Token统计，不是字符！**
8K、32K上下文窗口，上限是Token数量。
同样文字，中文、英文消耗token速度不一样；超出窗口会截断内容，长记忆Agent极易踩坑。

2. **API计费按照Token收费**
Prompt越长、示例越多、CoT思考文字越多，token消耗越高，成本上升。
少样本示例不要无限制堆砌。

3. **很多诡异bug根源来自分词差异**
- `2 + 2` 和 `2+2` 分词结果不同，模型正确率不一样
- 大小写、多余空格、特殊符号，会产生完全不同的token序列
- 自定义专有名词、英文复合词切分方式不可控

## 极简一句话记忆
分词器把文字转成模型能看懂的token数字；
开发Agent不需要实现BPE，但必须明白：**一切长度限制、费用、部分奇怪推理错误，都和Token息息相关。**

# 3.2.3 调用开源大语言模型（知识点 + 完整可运行代码整合版）
## 一、核心知识点
### 1. 两种大模型使用方式
1）云端API调用
优点：开箱即用，无需显卡；缺点：数据外传、持续付费、无法离线。
2）本地部署开源模型（本节内容）
适用场景：敏感数据、离线运行、长期运行控制成本、深度自定义提示流程。

### 2. 核心工具：Hugging Face Transformers
- `AutoTokenizer`：加载模型配套分词器，文本 ↔ Token ID 互相转换，**模型与分词器必须一一对应，不可混用**。
- `AutoModelForCausalLM`：加载因果生成类大模型（Qwen、GPT系列这类对话生成模型）。

### 3. 完整推理流程
1. 选择模型，加载分词器与模型，自动选择GPU/CPU设备
2. 构造标准化对话 `messages`：`system` / `user` / `assistant`
3. `apply_chat_template()`：套用模型专属对话格式模板
> ⚠️ 不要手动拼接特殊标记，格式错误会导致模型效果大幅下降；
> `add_generation_prompt=True` 标识后续由模型输出助手回复。
4. tokenizer编码：文本 → `input_ids`（Token数字序列）
5. `model.generate()` 自回归生成Token序列
    - `max_new_tokens`：限制**新生成的Token数量**，不含输入提示词
    - 可传入 `temperature、top_p` 控制输出随机性（前面学习的采样参数）
6. 切片截取：剔除输入Token，只保留模型新增生成内容
7. `tokenizer.decode()`：Token数字还原为自然文本

### 4. 常见踩坑
1. 忽略对话模板，手动拼接prompt；
2. 不解离输入token，最终回复重复带上提问内容；
3. 分词器与模型不匹配；
4. 混淆 `max_new_tokens` 和上下文总长度。

## 二、完整代码（带注释，融入上面知识点）
```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

# 模型地址：轻量对话模型，适合本地入门测试
model_id = "Qwen/Qwen1.5-0.5B-Chat"

# 自动选择运行设备：优先GPU(cuda)，无GPU使用CPU
device = "cuda" if torch.cuda.is_available() else "cpu"
print(f"运行设备：{device}")

# 1.加载分词器、生成模型（成对加载，不可混用其他模型的tokenizer）
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id).to(device)

# 2.构造标准对话结构 system(角色) + user(用户提问)
messages = [
    {"role": "system", "content": "你是一名乐于助人的AI助手。"},
    {"role": "user", "content": "你好，请简单介绍你自己。"}
]

# 3.套用模型自带对话模板，自动拼接特殊标识符
# add_generation_prompt=True 代表等待assistant生成回复
text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True
)

# 4.文本编码：文字 → Token数字ID
model_inputs = tokenizer([text], return_tensors="pt").to(device)

# 5.模型生成，可配置温度、top_p等采样参数
generated_ids = model.generate(
    model_inputs.input_ids,
    max_new_tokens=512,   # 限制最多新生成512个token
    temperature=0.7,      # 随机性，越低答案越稳定
    top_p=0.8
)

# 6.切片：去掉输入部分token，只保留模型新生成内容
generated_ids = [
    output_ids[len(input_ids):]
    for input_ids, output_ids in zip(model_inputs.input_ids, generated_ids)
]

# 7.解码：Token数字 → 可读文本，skip_special_tokens去除特殊符号
response = tokenizer.batch_decode(generated_ids, skip_special_tokens=True)[0]

print("模型输出：")
print(response)
```

不需要掌握模型权重训练、量化底层；
重点掌握**整条调用链路**，理解本地推理如何串联前面学到的「Tokenizer分词、提示工程、采样参数」知识点。
后续开发本地运行的智能体，就是基于这套代码扩展循环调用、工具调用逻辑。

# 3.2.4 模型的选择｜精简总结（适合笔记/复习）
## 核心总起
模型选型**不盲目追求参数最大、性能最强**，是在**性能、成本、速度、部署方式**之间综合权衡；分为闭源商用模型、开源权重模型两大路线，是开发Agent智能体的关键前置决策。

## 一、模型选型8大核心考量维度
1. **性能与能力**
不同模型擅长任务不同（推理、代码、写作、多模态），可参考公开评测榜单横向对比。
2. **成本**
- 闭源模型：API调用，按Token计费；
- 开源模型：无调用费，但需要承担GPU硬件、部署运维成本。
3. **延迟（响应速度）**
实时交互类Agent（客服、游戏NPC）优先选择轻量、高速模型。
4. **上下文窗口**
决定单次可处理文本长度；长文档分析、长期对话记忆场景，需要更大上下文窗口。
5. **部署方式**
API调用：上手简单，数据外发；本地部署：隐私可控、支持离线，硬件与技术门槛更高。
6. **生态与工具链**
热门模型拥有更完善教程、框架兼容（LangChain、HuggingFace）、社区问题解决方案。
7. **可微调&定制化**
行业专属场景需要微调；开源模型自由度远高于闭源模型。
8. **安全性与伦理**
关注幻觉、偏见、有害输出；面向公众、敏感业务必须评估安全能力。

## 二、闭源模型概览（只能调用API，无法拿到模型权重）
特点：前沿能力强、稳定、开箱即用；数据需要传给服务商，无法本地私有化。
1. **OpenAI GPT系列**
行业标杆，多模态、指令对齐优秀；适合复杂推理、通用Agent开发。
2. **Google Gemini系列**
原生多模态，超长上下文；擅长图文、音视频混合任务。
3. **Anthropic Claude系列**
主打AI安全，长文档处理能力突出，企业级场景常用。
4. **国内闭源模型**
文心一言、腾讯混元、星火、月之暗面等；**中文原生优势**，适配本土业务。

## 三、开源模型概览（可下载权重，本地部署、微调）
特点：高度自主可控，数据不外流，支持离线运行；需要硬件与部署能力。
1. **Meta Llama系列**
开源模型标杆，社区生态庞大；Llama4支持超长上下文、MoE混合专家架构。
2. **Mistral AI系列**
小体积高性能，推理速度快，原生多模态。
3. **国内开源模型**
阿里Qwen（通义千问）、智谱ChatGLM；中文能力优秀，国内学习部署首选（你之前运行的Qwen1.5就属于该系列）。

## 四、最终核心结论
✅ **闭源模型**：快速开发、验证项目，追求稳定强大能力，适合原型与对公服务；
✅ **开源模型**：数据敏感、需要离线、长期大量调用、深度自定义微调场景；
二者没有绝对优劣，根据智能体项目需求完成权衡选型。

# 3.3 大语言模型的缩放法则与局限性｜精简总结
## 3.3.1 缩放法则（Scaling Laws）
1. **核心定义**
模型性能与**参数量、训练数据量、计算量**三者呈可预测的幂律关系；在资源充足前提下，同步扩大三者，模型能力会平稳提升。

2. **Chinchilla定律（关键修正）**
不要单纯盲目堆参数量。在固定计算预算下，**模型大小和训练数据存在最优配比**：更小的模型 + 更多训练数据，往往比超大参数量、少数据的模型效果更好。打破了“模型越大越强”的误区。

3. **涌现能力**
模型规模跨过某个阈值后，突然出现小模型不具备的全新能力：多步推理、CoT思维链、代码生成、指令遵循等。
> 对Agent开发意义：复杂规划、自主决策的智能体，往往需要达到一定规模的模型才具备基础能力。

---
## 3.3.2 LLM核心局限：幻觉（Hallucination）
1. **幻觉含义**
模型自信地编造不存在、和事实/上下文冲突的虚假信息。
三类常见幻觉：
- 事实性幻觉：输出违背现实客观知识
- 忠实性幻觉：摘要/翻译偏离原文
- 内在幻觉：回答和用户输入上下文自相矛盾

2. **幻觉根本原因**
LLM只是**预测下一个最合理Token**，没有内置事实判断、现实感知能力；外加训练数据存在错误、长文本推理容易逻辑断裂。

3. 附带其他短板
- **知识截止**：知识锁定在训练数据截止时间，无法获取实时新信息
- **偏见问题**：继承训练数据里人类的刻板印象

4. **工程缓解方案（重点，Agent开发高频使用）**
- 数据端：清洗高质量数据、RLHF对齐
- 推理应用端：
  ✅ **RAG检索增强生成（最主流）**
  ✅ 多步自我验证思维链
  ✅ 接入外部工具（搜索、计算器等）

> 注意：现有手段**只能降低幻觉概率，无法彻底根除幻觉**。
